> 규격은 연구 파트의 `docs/23_ai_review.md`(R) 를 **그대로** 따른다 — 판별 질문,
> 다섯 절, 「재사용 규칙이 없으면 R 이 아니다」. 번호만 `UR-n` 으로 나눈다
> (`docs/ui/00_index.md`).
>
> **판별 질문**: "이건 이 화면에 관한 교훈인가, **AI 를 쓰는 방법**에 관한 교훈인가?"

## UR-1. 도구 추천을 카탈로그 없이 했다 — 외부 AI 도, 그리고 나도 한 번

| | |
|---|---|
| 대상 | 외부 저장소 `05_TOOL_SKILL_ROUTING.md` 의 도구 목록, 그리고 이 세션의 `docs/ui/03_external_system_review.md` 6 절 |
| 처리 | **부분 채택** — 역할 분류는 채택, 도구 이름은 재접지, Flourish 판정은 뒤집음 |
| 연결 | UD-5 · `03` 4-F · 6 절 · `04_tools.md`. 외부 R-001 · R-003 (인용) |

### AI 가 내놓은 것

외부 AI 는 「설치/연결 확인」 표에 여덟 도구를 올렸다 — GitHub · Product Design · Figma ·
Creative Production · Flourish · Context7 · TinyFish · Vercel. 이 세션의 나는 그 표를 받아
**카탈로그를 실제로 검색**해 「Creative Production」「Product Design」이라는 이름의
플러그인이 이 조직에 없음을 확인했고, 외부안이 놓친 공식 `frontend-design` 을 찾았다
`[플러그인]`. 거기까지는 맞았다.

그런데 Flourish 는 **「`dataviz` 가 이미 있으니 차트 도구는 겹친다」로 읽어 OPTIONAL 로
내렸다** (`03` 6.2 절 초판).

### 사람이 문제 삼은 것

> "flourish 는 현재 만들었던 데이터들에 대해 스토리텔링과 명확한 시각화 디자인을
> 도와준다고 하던데, 우리 기존 데이터 관련 툴에서는 스토리텔링 부분이 좀 부족하지
> 않아? … 여러 종류의 다이어그램/그래프를 제안해주는 느낌이라 UI 를 이용해
> 개선시키는 방식과는 좀 다른가?" `[대화]`

외부 저장소의 **R-003 이 정확히 이 실수를 기록해 두었다** — 「Flourish 를 차트 도구로만
보아 연구 UI 의 핵심 가치를 늦게 인식했다」. 나는 그 R 을 읽고 검토서에 요약까지 해
놓고 **같은 자리에 섰다.**

### 검증 방법과 결과

1. **우리 쪽 스토리 자산을 셌다** `[코드]` — `docs/34_visual_plan.md` 4 절의 주장↔그림
   대조표, S 세트 14 장(`results/slides/`), 카드 3 안(`docs/33`). 전부 **정지 그림의
   목록**이다. 「관람객이 15 초 안에 따라갈 한 줄기 순서」와 「같은 그림이 조건에
   따라 바뀌는 전환」은 어디에도 없다. 부족한 것은 차트가 아니라 **순서와 전환**이고,
   `dataviz` 는 그리기 규격이지 순서를 주지 않는다.
2. **Flourish 커넥터의 실제 범위를 공식 문서로 확인했다** `[문헌]` — MCP 는 데이터를
   받아 템플릿을 고르고 **단일 시각화**를 만들고 데이터 바인딩·설정을 편집한다.
   **Stories(여러 상태를 순서로 잇고 전환을 애니메이션하는 것)는 Flourish 편집기에서
   만든다.** 즉 이 도구의 값은 「어떤 관계(rank · slope · trade-off · before/after)가
   이야기를 전달하나」를 **빠르게 여러 벌 만들어 보는 것**이고, 최종 화면 생성기가
   아니다 — 외부 D-003 의 「탐색 엔진」 분류가 맞았다.
3. **무빌드 시연과의 관계** `[코드]` — Flourish 결과는 외부 임베드라 `file://` 로 여는
   시연(UD-1 §3.1)에 그대로 못 들어간다. 채택안은 Canvas/SVG 로 재구현하거나 정적으로
   내보내 쓴다. 그래서 「UI 를 개선하는 방식」과 다른 것이 맞다 — **UI 의 MEDIUM
   구역(결과 요약·metric reveal)에 무엇을 놓을지를 정하는 앞단**이다.

### 처리

- `04_tools.md` 에서 Flourish 를 DATA 역할의 **스토리 초안 도구**로 올렸다(켜야 함).
- 첫 실험은 UD 로 먼저 적는다: 한 문장 insight → 후보 3 벌(rank · slope · before/after)
  → `04_VALIDATION` 의 데이터 무결성 기준으로 KEEP/TUNE/REJECT → 채택안만 재구현.
- 검토서 `03` 6.2 절의 초판 판정은 지우지 않고 정정 표시를 남겼다.

### 재사용 규칙

1. **도구를 추천하기 전에 그 환경의 카탈로그를 실제로 검색하고, 표에 「확인한
   환경·날짜」열을 둔다.** 다른 환경에서 「설치 확인」한 것은 여기서 사실이 아니다.
2. **시각화 도구는 두 능력으로 나눠 평가한다 — 「그리기」와 「순서·전환(스토리)」.**
   그리기 도구가 있다는 것이 스토리 능력이 있다는 뜻이 아니다. 연구 시연에서 빈 것은
   대개 후자다.
3. **외부 저장소의 R 을 읽었으면, 그 R 이 경고한 자리에 왔을 때 자기 판정을 한 번
   더 본다.** 읽는 것과 적용하는 것은 다르다 — 이번에는 사용자가 잡았다.
