## 1. R-A — 심전도 표시 규약 `[측정]`

### 표준

| | 표준 | 뜻 |
|---|---|---|
| 가로 | **25 mm/s** | 소칸 1 mm = **0.04 s** · 대칸 5 mm = **0.20 s** |
| 세로 | **10 mm/mV** | 소칸 = **0.1 mV** · 대칸 = **0.5 mV** |
| 빠른 기록 | 50 mm/s | 부정맥을 볼 때. 소칸 = 0.02 s |

격자가 이 규약을 지키면 **세어서 읽을 수 있다** — RR 간격, PR, QT. 임상의가 화면을
보는 방식이 그것이다.

### 우리 화면은 어떤가 — **격자가 장식이고, 속도가 화면 폭에 딸려 간다**

CSS 에서 1 mm = 96/25.4 = **3.7795 px** 다. `demo/index.html` 은 구간 길이(10/4/2 s)를
고정하고 캔버스를 화면 폭에 맞추므로, **속도는 폭이 정한다**:

| 화면 폭 | 구간 10 s | 구간 4 s | 구간 2 s |
|---|---|---|---|
| **1920** (확정 표시 장치) | **49.6 mm/s** ← 우연히 표준 50 에 근접 | 124 mm/s | 248 mm/s |
| **1440** | 36.9 mm/s | 92 mm/s | 185 mm/s |
| **1280** (최소 방어폭) | 32.7 mm/s | 82 mm/s | 164 mm/s |

**같은 「10 s」 칩이 화면마다 다른 속도를 만든다.** 표준과 맞는 것은 1920 에서
10 s 하나뿐이고 그것도 의도가 아니라 우연이다.

그리고 `mockup_expo.html` 의 격자는 **15 px 고정**이라 어떤 시간에도 대응하지 않는다.
`index.html` 의 세로선은 1 초 간격이라 눈금으로는 맞지만 **대칸/소칸 구분이 없다.**

세로는 더 멀다 — 진폭을 `ylim` 으로 정규화하므로 **mV 눈금이 아예 없다.** 은행은
`Int16 × scale` 로 담고 원 신호가 mV 이므로 **환산은 가능하다.**

### 판정

| | 항목 | 판정 |
|---|---|---|
| **발전** | 격자를 **규약에 맞춘다** — 대칸 0.2 s, 소칸 0.04 s | **채택.** 지금 격자는 장식이라 아무 비용 없이 의미를 얻는다 |
| **지적** | **구간 길이가 아니라 속도를 고정한다** | 칩을 「10 s · 4 s · 2 s」가 아니라 **「25 mm/s · 50 mm/s」**로. 화면에 보이는 시간은 폭이 정한다(1920 → 19.9 s / 9.9 s). 확대는 **한 박동 렌즈**가 따로 맡는다 (`docs/31` 1.2) |
| **추가** | 세로를 **mV 배수로 스냅** | `ylim` 을 임의값이 아니라 ±1.0 / ±1.5 / ±2.0 mV 로. 그래야 대칸 0.5 mV 가 의미를 갖는다. **「모든 칸이 같은 y 축」 규칙은 그대로 지켜진다** |

> **차용 경계 — 빌리면 안 되는 것이 여기 있다.**
> 감시장치는 IEC 60601-1-8 에 따라 **적색 = 고우선 알람 · 황색 = 중우선**을 쓰고,
> 파라미터마다 색이 고정돼 있다(ECG 녹색 · SpO₂ 청록 …). **우리는 이것을 빌리지
> 않는다.** CLAUDE.md 가 「임상·진단 능력을 주장하지 않는다 — 연구용 신호처리
> 시스템」이라고 못 박았고, 알람 색 체계를 그대로 쓰면 **화면이 의료기기라고
> 말하게 된다.** 격자는 읽는 방법이고 알람 색은 의학적 주장이다 — 전자만 빌린다.

우리 질문은 「입력 ↔ 출력 ↔ 참값을 어떻게 나란히 보이나」다.

| | 항목 | 판정 |
|---|---|---|
| **발전** | **레인(facet)이 이미 옳은 해법이다** | `dataviz` 가 「too many series」의 해법으로 드는 것이 facet 이고, `card_core.js` 의 `drawLane()` 이 그것이다. **색 부담을 레인이 이미 덜고 있다**(UF-1) |

| — | radar · scatter | **`[해당 없음]`** — 스킬이 비교 차트로 드는 형식이지만 우리 데이터는 시계열이다 |

## 4. R-D · R-E · R-F — 레이아웃 · 타이포 · 반응형

`ui-ux-pro-max` 119 가이드라인에서 우리에게 걸리는 것:

|---|---|---|

| Medium | 「**일관된 모듈러 스케일**을 쓰고 임의 크기를 쓰지 마라」 | 8~10 단계 난립, 그중 넷은 1 px 이내(U-8) |

| Medium | 「터치 타깃 사이 8 px 이상」 | 칩 간격 5~6 px |
| High | 「가로 스크롤 금지 · 고정 px 컨테이너 금지」 | `@media` **0 개**(U-9) — 다만 화면 검사는 세 폭에서 넘침 없음을 확인했다 |

| | 항목 | 판정 |
|---|---|---|
| **지적** | **파형이 고정 높이다** — Critical 규칙에 정면으로 걸린다 | 3 단계의 첫 목표. 세로 공간을 먹고 자라게 한다 |

| **추가** | 조작 요소 간격을 8 px 이상으로 | 관람객이 직접 만지는 것이 기본이다(`docs/ui/01_system.md` 7 절) |

## 8. 레퍼런스 카드 — 시안 이전의 저비용 시각 정렬 (UD-10)

> 원본 `ecg-gui-design-review` `13_REFERENCE_GROUNDED_CREATIVE_MINING.md`(`08ffec3`)에서
> **규격만** 들였다. 그쪽 발견(F-004 「레퍼런스는 inspiration 이 아니라 **AI 와 사람이 같은
> 장면을 보는 대리물**이다」)이 이유다 — 텍스트 후보는 이해돼도 **느낌은 공유되지 않는다.**
> 후보마다 시안을 만드는 대신 실제 장면을 함께 본다.

### 8.1 카드 규격

```
REF-nn
출처 · URL
어디를 볼지          ← 필수. 「홈 열고 첫 0~5 초 reveal 만. 아래 섹션은 무관」처럼 장면·시간·스크롤·조작을 짚는다
잊히지 않는 순간
기제 (왜 먹히나)
기대 감각
프로젝트 번역        ← 구역(HIGH/MEDIUM/LOW) + 무엇을 절대 안 바꾸나(파형·시간축·단위·Reference/Difference)
복사 금지 목록       ← 원본의 팔레트·서체·오브젝트·셰이더 중 원리와 무관한 것
Imitation Distance   ← 0 복제 · 1 외형 · 2 레이아웃/기제 · 3 상호작용 원리 · 4 추상 경험 원리. 기본 3~4. 0~2 면 이유를 적는다
위험
최소 시안
장면 서술            ← **카드를 살리는 것은 이것이다.** 링크가 죽거나 사이트가 바뀌어도 남는다
L1 캡처              ← results/screens/refs/round<N>/REF-nn.png. **커밋된다** — `.gitignore` 를 `results/screens/*` + `!results/screens/refs/` 로 고쳤다(UD-11 추기). 원본이 사라져도 카드가 산다. 다만 **장면 서술과 「어디를 볼지」가 여전히 본체다** — 캡처는 그것을 뒷받침할 뿐이고, 제 3 자 화면을 담는 것이므로 인용 범위를 넘기지 않는다
```

번역은 반드시 네 단계를 거친다: **레퍼런스의 특징 → 경험 원리 → 이 프로젝트에서의 뜻 →
구현 후보.** 원본 오브젝트를 그대로 가져오는 것은 기본값이 아니다.

### 8.2 소스 — 우리 범주가 먼저다

| 찾을 것 | 어디서 | 구역 |
|---|---|---|

| 과학 전시의 「들어감·확대·규모」 | NASA Eyes · 과학관 인터랙티브 · 데이터 저널리즘(NYT/Pudding) | HIGH · MEDIUM |
| 편집 타이포 · 큰 숫자 하나 | SiteInspire · Land-book 류 | MEDIUM |
| wow 3 초 · 시네마틱 전환 | Awwwards · Godly | **HIGH 만** |
| 상용 제품 흐름의 익숙함 | ~~Mobbin~~ **기각 유지**(UD-1) — 웹 조사로 대신 | — |

플랫폼 이름이 품질 보증이 아니다. 필요한 **경험 원리**에 맞는 장면을 고른다.

### 8.2.1 **허브는 사용자가, 탐색은 디렉터가** — B 의 레퍼런스 경로 (UO-6 뒤)

> **먼저 정정한다.** 이 절의 초판은 사용자에게 「URL 6~10 개 + 각각 어디를 볼지 한 줄」을
> 달라고 적었다. **역할이 뒤집힌 규격이었다** `[대화]` — 사용자 지적: 「기존 방식에선 그냥
> UI 모음집 같은 사이트를 주면 거기서 네가 여러 UI를 탐색해보다가 … 어떤 UI의 어떤 부분을
> 이용해보라고 주는 건 아니었어」. 맞다. **「어디를 볼지」는 본 사람만 쓸 수 있고, 그것을
> 사용자에게 시키면 사용자가 디렉터가 된다.**

| 누가 | 무엇 |
|---|---|
| **사용자** | **허브 1~2 개.** UI 모음집·갤러리 URL 하나면 된다. 그 이상 안 줘도 된다 |
| **디렉터** | 허브를 **탐색**하고, 참신한 작동 방식·시각 효과를 **고르고**, 「어디를 볼지」를 **쓰고**, §8.1 카드 12 칸을 채운다 |

**`extract-website` 는 탐색을 못 한다** `[문헌]`. 허브 URL 을 주면 **허브 자신의 디자인**을
뜯어 온다(갤러리 사이트의 색·서체), 전시된 작품이 아니라. 순서가 이렇다:

```
허브 → (탐색·선별: 브라우저가 열리는 세션이 한다) → 고른 작품 URL
     → extract-website --url <작품> --design-md --brand-assets → 카드
```

**그래서 탐색은 어디서 되나** `[측정]` (2026-09-20):

| | |
|---|---|
| `awwwards.com` · `godly.website` · `siteinspire.com` · `land-book.com` | **전부 `000`** — 이 환경에서 갤러리 탐색은 **불가능**하다 |
| `github.com`(HTML) | `400` / `403` |
| **`api.github.com`** | **`200`** |
| **`raw.githubusercontent.com`** | **`200`** — 이미지도. 41 KB PNG 를 받아 **실제로 열어 봤다** |

→ **갈래가 둘이다.**

- **ⓐ-1 로컬 갤러리** — 사용자가 허브를 주고 **로컬 세션**이 탐색한다. A 가 돈 방식 그대로다.
  진짜 UI 모음집이라 「craft · wow 3 초」 칸이 강하다. 계정·네트워크 필요.
- **ⓐ-2 GitHub 허브 — 여기서 오늘 된다.** `api.github.com` 으로 검색하고 README 의
  스크린샷·데모 GIF 를 `raw.githubusercontent.com` 으로 **열어 본다.** 갤러리가 아니라
  오픈소스라 「craft」 칸은 약하고 **「계측·시각화의 실제 구현」 칸은 강하다.**
  A 도 B 도 안 쓴 갈래다.

**A 가 라운드 ① 에 쓴 7 은 B 가 안 쓴다** — 겹치면 두 디렉터가 한 소스로 수렴한다:
`skillstat.com` · `dood.al/oscilloscope` · `earth.nullschool.net` · `eyes.nasa.gov` ·
Bloomberg warming(2015) · USGS 헬리코더 · 스플릿플랩(Wikipedia).

**디렉터가 채우려고 탐색할 칸 여섯** — 앞 넷은 A 가 **안 본 칸**이고, ③④ 는 **원본 없는
후보에 원본을 준다**(UO-6):

| 칸 | 찾을 것 | 우리 쪽 쓸 곳 |
|---|---|---|

## 10. 3 m 가독 — 「멀리서 읽힌다」를 px 로 옮기는 자 `[측정]`

> UD-11 의 A5·A6 을 판정하려다 만들었다. 「3 m 에서 읽힌다」는 **잴 수 있는 조건**인데
> 그동안 말로만 있었다. 다음 라운드부터는 이 표를 먼저 본다.

사람 시각의 관례: 20/20 시력이 **1 arcminute** 획을 분해한다. 문자 **전체 높이**
기준으로 **5 arcmin = 겨우 판독 · 10 arcmin = 읽을 수 있음 · 20 arcmin = 편안**.

3 m 에서 그 각크기의 물리 높이: **5′ = 4.36 mm · 10′ = 8.73 mm · 20′ = 17.45 mm.**

`font-size` 로 환산하면 (1920 폭 · 16:9 · cap height ≈ 0.70 em, IBM Plex 기준):

| 대각선 | 폭 | px/mm | 판독 5′ | **읽기 10′** | 편안 20′ |
|---|---|---|---|---|---|
| 13.3" | 294 mm | 6.52 | 41 px | **81 px** | 163 px |
| **15.6"** | 345 mm | 5.56 | 35 px | **69 px** | 139 px |
| 17.3" | 383 mm | 5.01 | 31 px | **62 px** | 125 px |
| 24" (외부 모니터) | 531 mm | 3.61 | 23 px | **45 px** | 90 px |
| 27" | 598 mm | 3.21 | 20 px | **40 px** | 80 px |

**쓰는 법**: HIGH 구역에서 3 m 를 겨냥한 글자는 **읽기(10′) 이상**. 다가온 사람이
읽는 규약·단위 줄은 **판독(5′)** 으로 족하다 — 3 m 대상이 아니다.
현재 `layout_b` 의 `--t-tick` 은 **13 px** 로, 어느 화면에서도 3 m 판독에 못 미친다.

**이 표가 화면 크기에 딸려 있다는 것이 요점이다** — 13.3" 와 27" 가 **두 배** 차이다.
UD-1 은 「노트북 1920×1080」만 적고 **인치를 안 적었다**(UF-10).

## 11. VS — 창의성·시각적 놀라움 **줄세우기** (UD-12)

**이 절이 있는 이유.** 검증기 넷은 **계약 대조**다 — 파형·시간·단위·대비·모션에는
통과선이 있다. 「더 놀랍다」에는 없다. 통과선 없는 것을 통과/실패 도구로 재면 **안 걸린
것이 전부 동점**이 된다. 라운드 ① 에서 KEEP 이 5 개 나왔고, 그중 무엇이 더 과감한지는
아무 데도 안 적혔다. VS 가 그 자리를 채운다.

**VS 가 아닌 것**: 판정이 아니다. **아무것도 떨어뜨리지 않는다.** 순서만 만든다.

### 11.1 언제 도는가

```
발산 A · B  →  [VS 줄세우기]  →  사용자 정렬  →  (사용자가 고른 1~2 → 시안 생성)  →  검증기 넷  →  KEEP/TUNE/REJECT  →  UD
```

검증기 **앞**이다. 뒤로 가면 사용자는 남은 것만 보게 되고 고르는 일이 판정이 된다(UO-5).
그리고 VS 순서 자체가 **사용자 정렬 단계에서 사용자가 읽을 자료**다.

### 11.2 네 가지 물음 — 각 후보에

| # | 물음 | 어떻게 답하나 | 실패 모습 |
|---|---|---|---|
| **V1** | **주제 교체 시험** | 후보 설명에서 「ECG · 기록지 · 계측기 · 잡음 · mV」를 「주가 · 날씨 · 음악」으로 바꿔 읽는다. 문장이 **그대로 성립하면** 그 후보는 주제에서 나온 것이 아니다 | 「데이터가 흐르고 카드가 떠오른다」 — 무엇에나 된다 |
| **V2** | **클리셰 대조** | `frontend-design` 클리셰 5 항(크림+세리프+테라코타 · 니어블랙+애시드 · 브로드시트 · SaaS 카드킷 · 템플릿 크롬)과 **UD-6·UD-9 가 이미 기각한 것**에 걸리나 | 배경 파티클, 글로우, 히어로 중앙정렬, 카운트업 |
| **V3** | **하루 뒤 한 문장** | 이 후보를 **하루 뒤에 한 문장으로** 말할 수 있나. 그 문장을 적는다 | 적은 문장이 「깔끔하다 / 모던하다 / 전문가스럽다」면 **0 점** — 그건 후보가 아니라 인상이다 |
| **V4** | **대담함 개수** | 대담한 요소를 **센다**. **1 개가 최고.** 0 은 안전하고 잊힌다, 2 이상은 서로를 잡아먹는다(「대담함은 한 곳에」 · 샤넬의 액세서리) | A6 이 이 항에 걸렸다 — 큰 숫자 **와** 컷 전환 둘 |

V1·V2·V4 는 **대조표가 있으니 재현된다.** V3 만 판단이고, 그래서 **문장을 반드시 적는다** —
적힌 문장이 다음 사람의 검증 대상이 된다.

### 11.3 규칙 셋 — 이것이 없으면 줄세우기가 아니다

1. **동점 금지.** N 개면 1 위부터 N 위까지. 「공동 2 위」를 쓰지 않는다.
2. **이웃 한 줄.** n 위가 n+1 위보다 **왜** 위인지 한 줄씩. N−1 줄이 나온다.
   이 줄들이 VS 의 실제 산출물이다 — 순위표만 있으면 읽을 것이 없다.
3. **줄세우는 사람은 만든 사람이 아니다.** 한 세션이 A·B 를 다 냈으면, VS 는
   **후보 표만 보고** 돈다 — 설계안·의도·근거 절을 다시 읽지 않는다. 자기 설명이 옆에 있으면
   자기 것이 올라간다.

### 11.4 적는 자리

라운드 폴더에 `vs_rank.md` 로 둔다 — `results/screens/refs/round<N>/vs_rank.md`.
UD 는 **순위표와 이웃 줄만** 요약해 싣는다. 발산 원문이 `dir_A.md`·`dir_B.md` 로 나간 것과
같은 규약이다(UD-12).

## 13. 구성 골격 메뉴 — **정확히 하나** 고른다 (UD-13)

**어디서 왔나**: Superdesign `GRAPHIC.md` 의 「Layout menu (pick exactly one)」 — 포스터 골격
다섯을 **닫힌 메뉴**로 주고 하나만 고르게 하며, 「슬로건 → type-hero, 공연 → full-bleed」식
**라우팅 힌트**를 붙인다. 장치만 빌렸고 내용은 우리 것이다(`06_superdesign_method_review.md` S5).

**왜 필요한가**: 라운드 ① 의 후보 열셋 중 **골격이 다른 것은 셋뿐**이었다 — 나머지는 현행
화면의 변주였다. 닫힌 메뉴에서 하나를 고르게 하고 **한 라운드에 같은 골격을 둘 금지**하면
변주가 구조적으로 불가능해진다.

**쓰는 법 셋**
1. 후보마다 골격 **하나**. 「① 과 ③ 을 섞어서」는 후보가 아니라 합류이고, 교차 검토에서 한다.
2. 한 라운드에 **같은 골격 둘 금지.** 셋째가 같은 골격이면 그 후보를 버리고 다시 낸다.
3. 골격은 **레이아웃**이지 스타일이 아니다. 색·서체는 여기서 안 고른다(S2 — 스타일은 고정).

### 메뉴 — 1920×1080 · 3 m · `px/mm = 3.793` · ±1 mV = **75.9 px**

| 골격 | 구성 | 기하 예산 `[측정]` | 무엇을 주장하나 | 무엇이 어려워지나 |
|---|---|---|---|---|
| **① 전면 한 레인** | 폭 전체를 레인 하나가 차지, 나머지는 얇은 띠 | 레인 1726 px = **9.1 s** | 「이건 진짜 심전도다」 — 물성·정직 | **비교를 못 보인다.** 레인이 하나라 방법 얘기를 꺼내면 거짓말이 된다 |
| **② 레인 스택** | N 개 레인을 세로로 동시에 | 7 줄 = 신호분만 **531 px**(7×75.9) + 줄간격 | 「조건이 바뀌면 답이 바뀐다」 — 기울기로 | 줄이 얇아진다. 그리고 쌓인 줄이 **연속된 한 기록**으로 읽히면 거짓 (우리 줄은 같은 10 s 의 다른 조건) |
| **③ 분할** | 화면을 둘로 — 한쪽 입력, 한쪽 출력, **같은 순간** | 반쪽 843 px = **4.4 s** — 60 bpm 에서 4 박동 남짓 | 「전후가 같은 시각이다」 | **보이는 시간이 반**이다. 9.1 s 를 전제한 문장·미니맵이 전부 안 맞는다 |
| **④ 중첩 한 축** | 모든 계열을 한 레인에 겹친다 | 레인 1726 px = 9.1 s, 계열 수만 늘어난다 | 「차이는 같은 자리에서 난다」 | **위험 최고.** 색만으로 신원이 갈리면 색각 위반, 참값은 paper 위 1.92:1 로 안 보인다(UD-11) |
| **⑤ 접촉 인화 격자** ★ | 98 장면을 작은 타일 격자로 **한꺼번에** | 10×10 → 타일 ≈185 px = **0.98 s** — 타일 하나가 **한 박동** | 「한 장면이 아니라 실험 전체다」 — 규모·전수 | 타일은 3 m 에서 **패턴으로만** 읽힌다. 개별 값은 다가와야 한다 — 그게 결함이 아니라 설계여야 |
| **⑥ 테두리 주행** ★ | 가운데는 비우고 파형이 화면 **테두리**를 따라 돈다 | 둘레 직선 구간만 합쳐 ≈5,400 px = **28 s** | 「이 방은 계측 중이다」 — 화면이 아니라 공간의 상태 | **모서리에서 기하가 깨진다.** 꺾지 말고 **끊어야** 한다(R-A). 끊으면 시간이 끊긴 것으로 읽힐 위험 |
| **⑦ 기록계 + 로그** ★ | 레인 옆에 **방금 한 일이 역순으로 쌓이는 로그 패널** | 레인 1446 px = **7.6 s** + 로그 280 px | 「쉬지 않고 돌았다」 — 활동을 **모션이 아니라 목록**으로 | 로그가 **읽을 것을 늘린다.** 3 m 에선 글자가 아니라 **쌓이는 덩어리**로만 읽혀야 한다 |

★ = **라운드 ① 에서 아무도 안 쓴 골격.** ⑦ 은 **라운드 ③ 의 레퍼런스가 가져왔다**
(REF-01 Goya 의 History 패널). 메뉴에 없던 골격이 나오면 **메뉴를 늘린다** — 그게 레퍼런스가 일하는 방식이다.

**라우팅 힌트** — 무엇을 주장하려는지로 고른다:

| 주장하려는 것 | 골격 |
|---|---|
| 정직성 · 물성 (「진짜 기록이다」) | ① |
| 조건에 따른 변화 · 추세 | ② |
| before / after · 동시성 | ③ |
| 미세한 차이 · 겹쳐야 보이는 것 | ④ (위험 검토 필수) |
| 규모 · 전수 · 「골라 보여 준 게 아니다」 | ⑤ |
| 존재감만 · 내용은 다가와서 | ⑥ |
| 지속 · 「계속 하고 있었다」 | ⑦ |

둘이라 ② · A4 = ② · A7 = ②의 시간판 · A8 = 골격이 아니라 **전이**. → **①이 일곱**이다.
