## UO-1. 한글 폰트가 없는 환경에서 그림을 만들어 **tracked 산출물을 깨진 것으로 덮어썼다**

| | |
|---|---|
| 시점 | UD-1 1 단계 — 팔레트 원본으로 전환한 뒤 「스크립트가 아직 도는가」를 확인하려고 |
| 상태 | **되돌림** (`git checkout`). 규칙은 이미 있었고 내가 안 지켰다 |

### 무엇을 했나

`python3 scripts/make_slides.py --only S5` 를 돌렸다. 목적은 **import 전환이
깨지지 않았는지 확인**하는 것이었는데, 이 스크립트는 확인만 하지 않는다 —
**그리고 저장한다.**

결과:

```
UserWarning: Glyph 51020 (HANGUL SYLLABLE EUM) missing from font(s) DejaVu Sans.
  S5_crossover.png
  docs/93_slides.md
```

이 컨테이너에는 한글 폰트가 없다. 그래서 **한글이 전부 두부(□)로 깨진 그림**이
`results/slides/S5_crossover.png` 를 덮었고, `docs/93_slides.md` 와
`results/slides/manifest.json` 까지 함께 바뀌었다. 셋 다 tracked 다.

### 어긋난 규칙 — 둘 다 CLAUDE.md 에 있었다

| 규칙 | 어떻게 어겼나 |
|---|---|
| **그림을 만들 때**: 저장 전에 검사하고 **눈으로 본다** | 저장하고 나서야 경고 줄을 읽었다. 그림을 열어 보지 않았다 |
| **산출물을 지우거나 덮어쓸 때**: tracked 산출물은 **새 것이 완성된 뒤에** 교체한다 | 「완성된 새 것」이 아니라 **깨진 것**으로 덮었다 |

### 왜 일어났나

**확인과 생성을 같은 명령이 한다.** 「import 가 깨졌나」를 묻고 싶었는데
`make_slides.py` 에는 그 질문만 하는 모드가 없다. `--only S5` 는 가장 작은
단위였을 뿐 여전히 **저장하는** 명령이다.

그리고 환경이 달랐다 — 이 컨테이너는 그림을 만들라고 준비된 곳이 아니다.
한글 폰트가 없다는 것을 **그림을 만들고 나서** 알았다.

### 조치

1. 즉시 되돌렸다 — `git checkout -- results/slides/S5_crossover.png
   results/slides/manifest.json docs/93_slides.md`.
2. **import 확인은 `ast.parse` 와 `import _palette` 로 한다.** 실제로 그 둘이
   먼저 통과했고, 그림 생성은 필요하지 않은 확인이었다.

### 규칙으로 승급시킬 것

> **그림 생성 스크립트는 「확인용」으로 돌리지 않는다.** 코드가 도는지 보려면
> `ast.parse`·`import`·`pytest` 를 쓴다. 그림을 만들어야 한다면 **한글 폰트가
> 있는 환경인지 먼저 확인**하고, 저장된 결과를 **열어 본** 뒤에 커밋한다.

이 저장소의 그림 산출물은 발표와 보고서에 그대로 들어간다. 깨진 그림이 조용히
섞이면 **커밋 이력만으로는 드러나지 않는다** — PNG diff 는 사람이 안 읽는다.

### 놓쳤다면

`S5_crossover` 는 `docs/34_visual_plan.md` 가 「**가장 설득력 있는 그림**」 계열로
꼽은 것 중 하나이고, 보고서 5.8.2 의 교차점 주장을 그대로 싣는다. 한글 라벨이
전부 두부로 바뀐 채 발표에 들어갔을 수 있다.

## UO-2. `pytest … | tail` 이 종료 코드를 가려서 **실패한 검사를 통과로 읽고 커밋·푸시했다**

| | |
|---|---|
| 시점 | 외부 UI/UX 시스템 검토서(`docs/ui/03_external_system_review.md`)를 커밋하면서 |
| 상태 | **바로잡음** — 실패 원인(없는 파일을 교차 참조)을 고친 커밋이 뒤따른다 |

### 무엇을 했나

「검사가 통과하면 커밋한다」를 한 명령으로 이었다:

```
python3 -m pytest tests/ -q 2>&1 | tail -6 && git add … && git commit … && git push …
```

pytest 는 **1 failed, 580 passed** 였다 — `test_doc_cross_references_resolve` 가
검토서 9 절의 가칭 `04_creative_data_motion.md` · `13_ai_collaboration.md` 를
**존재하지 않는 파일**로 잡았다(제안 단계의 이름을 실제 경로 형식으로 적었다).
그런데 `&&` 는 파이프라인의 **마지막 명령(`tail`)의 종료 코드**를 본다. `tail` 은
성공했고, 커밋과 푸시가 그대로 나갔다 `[로그]`.

### 어긋난 규칙

| 규칙 | 어떻게 어겼나 |
|---|---|
| CLAUDE.md 「커밋 전 `pytest tests/`」 | 돌리긴 했다. **결과를 읽지 않고 셸이 읽게 했는데, 셸이 보는 값이 틀렸다** |

### 왜 일어났나

출력을 줄이려고 `| tail` 을 붙였고, 파이프라인의 종료 코드가 마지막 명령의 것이라는
것을 잊었다. 검사와 커밋을 한 줄로 이은 것 자체는 좋은 습관이다 — **이음새가 틀렸다.**

### 조치

1. 검토서의 두 참조를 「제안 이름」임이 드러나는 형식으로 고쳤다 — 경로가 아니라
   가칭으로 적는다.
2. 다시 `pytest tests/` 를 돌려 **전부 통과를 눈으로 확인한 뒤** 커밋했다.

### 규칙으로 승급시킬 것

> 검사와 커밋을 한 줄로 이을 때 **`| tail` 을 쓰면 `set -o pipefail` 을 먼저 켠다.**
> 아니면 검사를 따로 돌려 요약 줄(`N passed`)을 **직접 읽고** 커밋한다.

이 검사(`test_doc_cross_references_resolve`)가 잡은 것은 진짜 결함이었다 — 아직 없는
파일을 있는 것처럼 가리키면 다음 세션이 그 파일을 찾는다. 검사는 제 일을 했고
**내가 그 결과를 버렸다.**

### 놓쳤다면

「검사 통과 후 커밋」이라는 이 저장소의 전제가 한 커밋만큼 거짓이 된다. 그 위에
다음 커밋이 쌓이면 어느 커밋부터 깨졌는지 역추적해야 한다.

## UO-3. `claude plugin uninstall` 이 **방금 만든 프로젝트 설정 파일을 비웠다**

| | |
|---|---|
| 시점 | UD-7 검증 중 — 사용자 범위 설치를 원점으로 되돌리려다 |
| 상태 | **되돌림** (다시 썼다). 잃은 것은 파일 하나와 몇 분 |

### 무엇을 했나

「프로젝트 설정만으로 되는가」를 재려고 **프로젝트 `.claude/settings.json` 을 먼저 쓰고**,
그 다음 앞서 해 둔 사용자 범위 설치를 지우려고 이 둘을 돌렸다 `[로그]`:

```
claude plugin uninstall frontend-design@claude-plugins-official
claude plugin marketplace remove claude-plugins-official
```

명령은 「Successfully uninstalled / removed」라고 답했다. 그런데 그 뒤 프로젝트 파일이
이렇게 돼 있었다:

```json
{ "enabledPlugins": {}, "extraKnownMarketplaces": {} }
```

### 왜 일어났나

`uninstall`·`marketplace remove` 는 **그 항목을 선언한 설정 파일을 찾아 거기서 지운다.**
내가 방금 프로젝트 파일에 그 둘을 적어 두었으므로, 사용자 범위를 지우라고 한 명령이
**프로젝트 파일**을 고쳤다. 「사용자 범위 설치를 지운다」와 「프로젝트 선언을 지운다」를
같은 명령이 한다는 것을 몰랐다.

커밋 전이라 `git checkout` 으로 되돌릴 수도 없었다 — **추적되지 않는 새 파일**이었다.

### 조치

순서를 뒤집었다 — **사용자 상태를 먼저 원점으로 돌리고, 그 다음 프로젝트 파일을 썼다.**
그 뒤 검증은 정상으로 돌았다(UD-7 표).

### 규칙으로 승급시킬 것

> **`claude plugin` 의 지우는 명령은 프로젝트 설정 파일을 고칠 수 있다.**
> 돌리기 전에 `.claude/settings.json` 이 **커밋돼 있는지** 보고, 아니면 먼저 커밋하거나
> 사본을 떠 둔다. 이는 명판의 「산출물을 지울 때 — 새 것이 완성된 뒤에 교체한다」와
> 같은 계열이고, **추적되지 않는 새 파일이 가장 약하다.**
