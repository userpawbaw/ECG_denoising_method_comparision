## UD-1. 시연 화면을 **디자인 시스템으로 다시 세운다** — 그리고 그 과정을 **도구·레퍼런스 비교 실험으로 설계한다**

> **이관**: 이 결정은 처음에 `docs/21_decisions.md` 에 **D-29** 로 적혔다. UI/UX
> 파트를 분리하면서 여기로 옮겼고, 원래 자리에는 이관 표시를 남겼다. 내용은
> 옮길 때 고치지 않았다 — 참조 경로만 새 위치로 바꿨다.


| | |
|---|---|
| 시점 | 사용자가 「demo 의 UI/UX 가 실망스럽다」며 외부 AI 대화(Figma·Mobbin·shadcn·Storybook·Playwright 파이프라인)를 가져와 재설계를 요청 |
| 상태 | **계획 확정 · 제작 전.** 계획서는 `docs/ui/01_system.md` |

### 갈림길 — **목적이 둘이다**

첫째는 화면을 고치는 것이다. 둘째가 이 결정의 성격을 정한다 —
**사용자의 목적에 「외부 도구와 외부 레퍼런스를 쓰면 결과물이 얼마나 달라지는가」를
보는 것이 포함돼 있다.** 산출 형태와 Figma 범위를 고른 이유도 거기에 있다.

그래서 이것은 단순한 구현 결정이 아니라 **비교 실험이고, D-28 의 기준이 그대로
걸린다 — 「측정할 수 없는 실험은 하지 않는다」(F-40).**

### 먼저 잰 것 — 화면 넷을 실제로 열었다 `[측정]`

headless Chromium 1440 폭. 아홉 가지가 나왔다(`docs/ui/01_system.md` 1 절).
무거운 넷:

- **같은 방법이 파일마다 다른 색이다.** `M_FE` 가 보고서에서 마젠타, 시연 시안에서
  황토, 본 화면에서 파랑이다. 본 화면은 방법 색이 없어 **네 칸이 전부 같은 파랑**이다.
- **`validate_palette.js` 가 저장소에 없다.** `docs/33` 이 그것으로 검증했다고
  적었는데 다른 세션의 도구였고 사라졌다 — **팔레트를 손대면 같은 자로 다시 잴
  수가 없다** (`docs/19_record_keeping.md` 6 절 위반).
- **타이포가 8~10 단계로 난립하고, `11·11.5·12·12.5 px` 넷은 눈으로 구분되지
  않는다.** 위계가 아니라 잡음이다.
- **`index.html`·`live.html` 의 `@media` 가 0 개다** — 반응형이 아예 없다.

뒤의 둘이 「미감적으로 별로」의 실체에 가장 가깝고, **실측이 알려주지 않는
종류**다. 이 과제의 결정이 거의 전부 자기 실측에서 나왔기 때문에 **관습과
미감에서 오는 것만 구조적으로 비어 있다.**

### 사라진 검증기를 찾았고, 돌려 보니 FAIL 이다 `[측정]`

`validate_palette.js` 는 **`dataviz` 스킬 안에 있었다** — 옵션 이름이 같고,
`docs/33` 이 기록한 `M_FE`↔`M04` ΔE 12.9 가 그대로 재현된다. 실제로 쓰이는
팔레트 넷을 전부 돌린 결과:

| 팔레트 | 판정 |
|---|---|
| 카드 3 색 | **ALL PASS** |
| **보고서·카드 7 색** (`make_slides` · `build_metric_cards`) | **FAIL** — `M02`↔`M01` 정상시야 12.3 |
| **시연 시안 4 색** (`mockup_expo`) | **FAIL** — 고전 황토↔입력 적갈 정상시야 14.0 |
| **시안 다크 4 색** | **FAIL** — 명도대 넷 다 이탈 |

**`docs/33` 이 검증한 것은 카드 3 색뿐이었다.** 그 결론은 카드에만 적용됐고,
**보고서 그림과 시연 시안은 검증을 통과한 적이 없다.** 시안의 FAIL 은 시연의
핵심 대비 — **입력 ↔ 고전 방법 출력이 색으로 안 갈린다**는 뜻이다.

검증기가 세션 밖 도구이므로 **같은 기준을 저장소 안에 다시 구현한다**(1 단계 첫
항목). 도구가 또 사라져도 자가 남아야 한다.

### 외부 스킬이 메운 것 — **축 1 의 첫 데이터 포인트**

`dataviz`(세션 내장)와 `ui-ux-pro-max`(MIT)로 같은 화면을 다시 훑어 **다섯이 더
나왔다** — 호버·툴팁 없음, 범례 없음(`index`), 표 뷰 없음, 시간축 라벨 없음,
`prefers-reduced-motion` 없음(스윕·스크롤을 돌리면서).

**전부 자기 실측만으로는 안 나오던 것들이다.** 그러므로 「외부 레퍼런스를
참고하면 결과가 달라지는가」의 답은 이미 부분적으로 나왔다 — **달라진다.**
다만 그 레퍼런스가 화면 DB 가 아니라 **규칙 묶음**이었다는 것이 이 판의 관찰이고,
그래서 **0 단계의 범위가 좁아졌다** — ECG 도메인 관습과 before/after 비교 UI 만
외부 조사로 남는다.

### 검토한 선택지

| | 안 | 판정 |
|---|---|---|
| 1 | 지금 화면을 손으로 다듬는다 | **✗** — 값이 네 파일에 흩어진 채라 같은 어긋남이 재발한다 |
| 2 | React + Vite + Storybook 전면 전환 | **✗** — `demo/index.html` 머리말(「시연 중에 실패할 계산이 없다」)과 D-18 을 철회해야 하고, 박람회 당일 새 실패 지점이 생긴다 |
| 3 | **무빌드 시연판 + 개발용 검증판 병행** | **✓ 채택** (사용자 판단) |
| 4 | Mobbin 구독 | **✗ 도구만 기각** — 아래 |

### 고른 것과 근거

**3 번.** 시연 산출물은 단일 HTML 로 두고 갤러리·스크린샷·검사만 개발 시점에
돈다. **실험 대상과 시연 산출물을 격리하는 것**이 이 선택의 핵심 값이다 —
도구 실험은 실패할 수 있는데, 실패가 박람회 당일 화면까지 번지면 실험 비용이
아니라 사고가 된다.

**대가 둘**:
- 두 벌 동기화. **시간 비용이 아니라 「조용한 어긋남」**이다 — `docs/33` 에서
  「세 안이 공유한다」고 적힌 채 B·C 가 첫 판 그대로였던 것이 이 종류다.
  **그래서 2 단계(화면을 여는 장치)가 선택이 아니라 전제다.**
- **비교 대상이 좁아졌다.** 무빌드를 고른 순간 shadcn 은 배제되고 Storybook 은
  빌드판 쪽에만 남는다. **이 판은 사실상 「Figma MCP 하나」를 잰다** — 결론을
  쓸 때 이 범위를 넘겨 말하지 않는다.

### 실험 설계 — 축 셋과 자

| 축 | 대조군 |
|---|---|
| **외부 레퍼런스 참고** | **있다** — 현 화면 전부가 「레퍼런스 없음」 판이다 |
| **검증 장치 유무** | **있다** — 지금까지 전부가 「장치 없음」 |
| **MCP 도구 사용** | **없다** — 3 단계에서 짝지어 만든다 |

**교란을 먼저 가른다.** 1·2 단계(팔레트 단일화 · 검증 장치)는 **MCP 없이도
된다.** 개선의 대부분이 거기서 나오므로, 그대로 두면 그 개선이 전부 「MCP 도입
효과」로 읽힌다 — F-9 가 경고한 사후 선택과 같은 구조다. 그래서 **1·2 단계는
공통 기반으로 깔고 3 단계에서만 경로를 둘로 가른다**(Figma 시안 ↔ 직접 HTML 시안,
같은 요구사항·같은 시점).

**자의 분해능**: n=1 이고 평가자가 한 명이라 **순위는 재고 크기는 못 잰다.**
사용자 합의 사항이며, 나중에 결론이 이 선을 넘지 않도록 적어 둔다.

### Figma 를 어디까지 쓰나 — **시안 보드이지 거울이 아니다**

사용자가 「디자인 시스템까지」를 택했다. 다만 Figma 를 「현재 화면을 반영하는
곳」으로 쓰면 **반드시 낡는다** — 코드를 고치는 순간 뒤처지고, 그 뒤에 사용자가
낡은 것을 보고 수정하게 된다(`docs/33` 의 Figma 판).

그래서 Figma 에 두는 것은 **「지금 화면」이 아니라 「제안 중인 대안」**이고,
현재 화면은 스크린샷으로 옆에 붙인다. 현재를 주장하지 않으므로 낡을 수가 없다.

토큰 값은 **양쪽 어디서 고쳐도 된다** — Variables ↔ `palette.json` 은 MCP 로
양방향 자동화가 된다. 처음 판은 「값의 원본은 저장소」라고만 적어 Figma 에서의
수정을 필요 이상으로 묶었는데, **실제 위험은 방향이 아니라 어긋남이 조용한
것**이다. 규칙을 「양쪽 다 고칠 수 있다. 단 어긋나면 드러난다」로 바꾸고, 대조
명령과 마지막 대조 시각으로 강제한다.

### 확정된 화면 규격 (사용자 판단)

| | 확정 |
|---|---|
| 표시 장치 | **노트북 1920×1080** (실 뷰포트 약 1920×910) |
| 최소 방어폭 | **1280×720** — 검사는 1280·1440·1920 세 구간을 돈다 |
| 테마 | **라이트·다크 둘 다.** 다크 스텝은 자동 반전이 아니라 **다시 고른다**(지금 것은 FAIL) |
| 조작 주체 | **관람객과 발표자 둘 다.** 기본을 관람객 기준(히트 타겟 ≥ 44 px · 자동 리셋)으로 잡고, 발표자용 상세는 「깊이」 뒤에 둔다 |

1920 이 기준이 되면서 U-3 의 성격이 바뀐다 — 파형 96 px 고정은 1920×910 에서
**화면의 다수를 비운다.** 반대로 여유가 생겨 표 뷰와 범례 자리도 함께 확보된다.

### 순서 — 앞 단계의 산출물이 있을 때만 다음으로

| 순 | 무엇 | 상태 |
|---:|---|---|
| **0** | **레퍼런스 분석** — 표시 규약 · 비교 UI · 대시보드 · **레이아웃/여백 · 타이포 · 반응형/상태/모션** | 대기 |
| 1 | 색 검증기 · 팔레트 단일 원본 · 토큰(타이포·간격 포함) 생성 | **검증기 ✅** (`scripts/validate_palette.py` — 참조 구현과 다섯 팔레트 전부 일치). 팔레트 원본은 다음 |
| 2 | **상태 갤러리 · 스크린샷 · 화면 검사** | 대기 |
| 3 | 레이아웃 재설계 — **경로 둘로 짝지어** | 대기 |
| 4 | 실패 상태 화면(끊김·lead-off)과 색각 이상 검증 | 대기 |

**3 번을 뒤에 둔 이유**: 바꾼 것이 나아졌는지 재는 자가 먼저 있어야 한다.
보기 좋아진 대신 대비가 무너지는 교환을 눈으로는 못 잡는다.

### 기각한 것과 이유

- **Mobbin/Refero 구독** — 모바일 앱 플로우 DB 이고 우리는 데스크톱 계측
  화면이다. **다만 도구를 기각한 것이 활동을 기각한 것은 아니다** — 이 문서의
  첫 판은 둘을 함께 버렸고 그건 오류였다. 벤치마킹은 공개 자료와
  `chrome --screenshot` 으로 되며 **0 단계로 승격했다.** U-8(타이포)·U-9(반응형)은
  그 단계가 아니면 나오지 않는다.
- **shadcn 컴포넌트 조달** — 우리 화면의 부품은 칩·슬라이더·캔버스 셋이고 이미
  있다. 못 만든 것은 **ECG 파형 패널**인데 registry 에 없다.
- **카드 세 안의 시각 언어를 하나로 통일** — 갈린 것이 **의도**다(`docs/33`:
  지나가는 사람 / 심사위원 / 다른 팀). 통일 대상은 본 화면 셋뿐이다.

## UD-2. 그림 색 **두 개를 ΔE 2 만큼 옮긴다** — 조합으로 재서 나온 최소 수정

| | |
|---|---|
| 시점 | UD-1 의 1 단계에서 검증기를 되찾은 직후, UF-1 로 진단을 정정하고 나서 |
| 상태 | **적용함** — `scripts/make_slides.py` · `scripts/build_metric_cards.py` |

### 갈림길

UF-1 로 실패가 **두 쌍**으로 좁혀졌다 — `M_FE`↔`M04` (정상시야 ΔE 12.9) 와
`M04`↔`M05` (13.7). 둘 다 상대가 `M04` 주황이다.

`M04` 를 옮기면 두 쌍이 한 번에 해결되지만, **`M04` 는 카드 3 안이 쓰는 슬롯 2**다
(`docs/33_card_design_samples.md`). 통과하고 있는 유일한 팔레트를 깨는 셈이라
**고정하고 상대 쪽을 옮겼다.**

### 검토한 선택지

| | 안 | 판정 |
|---|---|---|
| 1 | `M04` 를 옮긴다 | **✗** — 통과 중인 카드 3 색이 깨진다 |
| 2 | 팔레트 7 색을 전부 다시 고른다 | **✗** — UF-1 이 「과잉」이라고 판정한 바로 그 접근. 후보 탐색에서 **노랑이 갈색(ΔE 21.6)** 이 되는 답이 먼저 나왔다 |
| 3 | **`M_FE`·`M05` 를 통과하는 가장 가까운 값으로 스냅** | **✓ 채택** |
| 4 | 색을 그대로 두고 보조 부호(선 종류·질감)로 가른다 | **✗** — 정상시야 바닥 15 는 **보조 부호로 면제되지 않는다.** 색각이 정상인 사람도 구분을 못 하는 자리다 |

### 고른 것과 근거 `[측정]`

| 방법 | 전 | 후 | 이동 | 최악 정상시야 |
|---|---|---|---:|---|
| `M_FE` (front-end 단독) | `#e87ba4` | **`#e880b4`** | ΔE **2.2** | 12.9 → **15.1** |
| `M05` (Sameni EKS) | `#eda100` | **`#e4a824`** | ΔE **2.0** | 13.7 → **15.1** |

**ΔE 2 는 눈으로 거의 구분되지 않는다.** 분홍은 분홍으로, 노랑은 노랑으로 남으므로
보고서 그림의 인상이 바뀌지 않는다. 「통과하는 값 중 원래에서 가장 가까운 것」으로
고른 결과이고, 탐색 범위는 명도대·채도·대비를 먼저 통과한 3~4 만 색이었다.

적용 후 **슬라이드 세 조합과 카드 세 조합이 전부 ALL PASS** 다.

### 대가

`M_FE` 나 `M05` 가 들어간 그림은 **다시 그려야 한다** — `S4_noise_{d0,d1}` 와
`S6_safety` 둘이다(`scripts/make_slides.py --only S4 S6`). 색 값은 코드 한 곳에
있으므로 재생성으로 끝나고, **결론이나 수치는 건드리지 않는다.**

### 재생성이 아직 안 됐다 — 색 때문이 아니다 `[측정]`

`--only S4 S6` 을 돌렸더니 그림이 아니라 **체크포인트 적재**에서 멈췄다:

```
RuntimeError: Error(s) in loading state_dict for WaveletSubbandUNet:
  Missing key(s):    backbone.enc.0.0.c1.weight ...
  Unexpected key(s): backbone.enc.0.c1.weight ...
```

`M08` 의 저장된 가중치가 **현재 모델 구조와 키 모양이 다르다**(`enc.0.0` ↔ `enc.0`).
두 그림 다 `M08` 을 포함하므로 둘 다 막힌다.

**색 변경과 무관하다** — 색을 되돌린 상태(`git stash`)에서 같은 에러가 그대로
난다. 팔레트는 상수 딕셔너리이고 가중치 적재 경로를 지나지 않는다.

> **이것은 연구 파트 사안이다** — 모델 구조와 체크포인트의 정합 문제이고,
> UI 파트가 손댈 자리가 아니다. 여기서는 **그림이 아직 옛 색이라는 사실만**
> 기록해 둔다. 저장된 그림(`results/slides/`)은 tracked 산출물이므로
> 「새 것이 완성된 뒤에 교체한다」는 규칙대로 **그대로 두었다**(CLAUDE.md).

| | 상태 |
|---|---|
| 코드의 색 | ✅ 바뀜 (`make_slides.py` · `build_metric_cards.py`) |
| 검사 | ✅ 통과 — 조합 여섯이 전부 ALL PASS |
| 저장된 그림 | ⏳ **옛 색** — 체크포인트 정합이 풀린 뒤 재생성 |

### 검사

`tests/test_palette.py` 가 **팔레트를 코드에서 읽어** 조합별로 검증한다. 색을 또
바꾸면 검사가 자동으로 따라오고, 두 색이 원래에서 ΔE 5 이상 멀어지면 실패한다 —
「정체성을 지키면서 통과시킨다」는 이 결정의 요점을 고정한 것이다.

**a + 「체계만」.** 사용자의 걱정 — UI 의 시행착오가 연구와 섞인다 — 는 **보고서와 F/D/O 대장**에서
섞이는 것이 문제인데, 그것은 이미 막혀 있다: 대장이 다르고(UD/UF/UO), 보고서 검사가
`docs/ui/` 를 제외하며(`test_report_names_every_doc`), 진입점이 따로다(`00_index`).
저장소를 나누면 얻는 것은 「디렉터리 하나 덜 보인다」뿐이고 잃는 것은 검사기 하나다.

### 버린 것과 이유

위 표의 b · c. 그리고 ② 에서 **B 쪽 번호를 옮기는 안** — 인용이 더 넓다. ① 에서
**한쪽만 고르는 안** — 사용자 결정.

### 갈림길

체계가 실제로 무엇을 내놓는가. 이식만 하고 시운전을 안 하면 외부 저장소와 같은 자리에
선다(`03` 4-A — 검증 계층이 한 번도 돈 적이 없다). 그래서 **첫 실전을 기록으로 남긴다**:
brief 한 문장 → 두 시안의 실제 화면 → 발산 7 → 검증 → 후보.

**brief**: 박람회 관람객이 **3 초** 안에 「같은 심전도라도 잡음이 다르면 이기는 방법이
다르다」를 느끼고, **15 초** 안에 두 방법의 차이를 파형에서 보고, **60 초** 안에 수치로
확인한다. 연구용 시연이고 진단 기기가 아니다.

### 기준선 — 두 시안을 실제로 열어 본 것 `[캡처]`

| | `layout_b` (무빌드, 여기) | v2 (React, 외부) |
|---|---|---|
| 첫인상 | **계측기.** 종이 심전도 격자 · 직접 라벨 · 하단에 `50 mm/s · 10 mm/mV · 대칸 0.10 s × 0.5 mV` 자(尺) · 「연구 시연 · 진단 용도 아님」 칩 | **대시보드.** 히어로 문구 + 자간 벌린 ALL-CAPS 눈썹 라벨(`OBSERVE · COMPARE · UNDERSTAND`, `SAME INPUT · SHARED TIME`) · 가운뎃점 메타 문자열 · `↗` 붙은 버튼 — **공식 `frontend-design` 이 「생성된 페이지의 표지」로 이름 붙인 것 넷** |
| 어디가 대담한가 | 없다. 전부 같은 무게의 회색 도구 | 밝은 페이지 안의 **어두운 플롯 패널 하나** — 「대담함은 한 곳에」를 본능적으로 맞췄다 |
| 파형 면적 | 세 레인 각 ≈120 px, 폭 1730 px — 1920×900 에서 **위 290 px 가 칩 세 줄**이고 파형이 그 아래 눌려 있다 | 두 레인 각 ≈190 px, Difference ×5 레인 추가. 격자는 장식(UF-3 의 「속도가 화면 폭에 딸려 간다」 그대로) |
| 숫자 | `+10.20 dB M06 가 M04 보다 이 조건에서 앞선다` — 좋은 문장인데 **툴바처럼 생긴 띠**에 앉아 있다. 오른쪽 `축 평균 최고 … 차이 +6.83 dB` 는 읽히지 않는다 | 지표가 화면에 없다(별도 탭) |

| HIGH 구역 | **없다** | Attract 모드 있음 |

사용자 질문 `[대화]`. **이 항목의 발산·검증은 Fable 5.1 판이다**(사용자가 세션 모델을
`claude-fable-5-1` 로 바꾼 뒤 돌았다). 여기서 Opus 5 를 돌릴 수는 없다 — 그래서 **같은
brief · 같은 기준선 캡처 · 같은 스킬 둘**로 Opus 5 판을 따로 돌리고 아래 예측과 대본다.
자는 UD-1 4.4 와 같다 — **순위는 재고 크기는 못 잰다**(n=1, 평가자 하나).

| 무엇 | 예측 | 근거 |
|---|---|---|
| 축 5 개 × 후보 5 개 이상이 나오나 | **차이 없음** | 스킬이 강제한다 — 과정이 모델을 대신한다 |
| 후보가 「어느 대시보드에나 있는 것」인가 (클리셰 목록 대조) | Fable 이 **조금** 낫되, Opus 에 **기준선 캡처 + 클리셰 목록 + 2 패스 자기 비판**을 주면 차이가 **크게 준다** | 발산의 질은 「무엇을 보고 발산했나」에 더 많이 달렸다 |
| 검증이 계약 줄을 정확히 인용하나 | **차이 없음** (Opus effort `high` 이상) | 검증은 체크리스트 모양이다 |
| 문서 사이 모순을 잡나 (예: 외부 스윕 계약이 UF-4 보다 뒤라는 것) | Fable 우세 | 긴 맥락 종합 |
| 비용 | Opus 가 **반값**($5/$25 vs $10/$50 per MTok, `claude-api` 참조 스킬 2026-06-24 표) — 같은 돈으로 **두 판** 돌려 합칠 수 있다 | 문서 |

**Opus 5 로 비슷한 효과를 내는 기법** (전부 이 저장소의 체계 안에 이미 있는 것들이다 —
그것이 체계를 만든 이유다):

1. **보고 발산하게 한다** — 기준선 스크린샷을 입력에 넣는다. 기억으로 발산한 후보는 어느 모델이든 평범하다.
2. **축과 개수를 강제한다** — 다섯 축 × ≥5, 후보마다 구역·시안·위험·검증 항목 칸을 채우게.
3. **클리셰 목록을 주고, 후보마다 「피한 기본값이 무엇인가」를 쓰게 한다.**
4. **2 패스** — 계획을 내게 하고, 「비슷한 brief 면 똑같이 나올 부분」을 스스로 고치게 한다(`frontend-design` 의 방법).
5. **역할을 호출로 가른다** — 발산 호출과 검증 호출을 따로. 한 호출에 「창의적이되 안전하게」를 시키면 평균으로 수렴한다(외부 D-001 · 우리 UD-5).
6. **기각 대장을 먹인다** — `10_decisions` 의 「버린 것」을 입력에 넣어 되살아나는 것을 막는다.
7. **두 판 돌려 합친다** — 반값이니 n=2 로 돌려 축별로 중복을 빼면 다양성이 는다.
8. **effort 는 `high`~`xhigh`** — 발산은 `high`, 검증은 `xhigh`. 참조 스킬은 「최신 모델의 낮은 effort 가 이전 세대의 높은 effort 를 넘는 일이 잦다」고 적는다 — 모델 등급보다 effort 와 입력이 먼저다.
9. **구조 후보에는 ASCII 와이어프레임을 요구한다** — 말로만 된 후보는 검증이 안 된다.
10. **검증 호출에 계약 원문을 붙인다** — `docs/21` §7 계열 · `02_benchmark` · UF-4. 검증기는 문서를 읽을 때 강하고 기억할 때 약하다.

Opus 판이 돌면 결과를 이 항목 아래에 `[측정]` 으로 덧붙이고, 예측이 틀린 칸은 지우지 않는다.

### 고른 것과 근거 — 아홉을 하나씩 세어 봤다 `[코드]`

| MCP | 이 프로젝트에서 |
|---|---|
| `figma` | **이미 커넥터로 켜져 있다** — 중복 |
| `slack` · `asana` · `atlassian` · `linear` · `notion` · `intercom` | **쓸 자리가 없다.** 졸업과제에 팀 이슈추적기·워크스페이스가 없다 |
| `google calendar` · `gmail` | **URL 이 빈 문자열**이라 애초에 안 붙는다 |

**아홉 중 새로 쓸 것이 0 개다.** 「MCP 는 유용하다」는 참이고, 그래서 **유용한 것은 이미
켜져 있다** — Figma · Flourish · MDN(사용자가 연결). 이 묶음은 그 일반론의 예가 아니다.

가져온 것은 둘뿐이다:

- **`accessibility-review`** — WCAG 2.1 AA 조항 번호까지 있는 짧은 대조표
  (1.4.3 대비 4.5:1 · 2.5.5 터치 타깃 44×44 · 2.4.7 포커스 표시 …). `ecg-ui-validator`
  의 접근성 절이 「대비 · 히트 타깃 · 포커스」로 뭉뚱그려 있던 자리를 **조항으로** 채운다.
- **`design-critique`** — 다섯 축 비평틀. 첫 축이 **「2 초 첫인상: 무엇이 먼저 눈에
  드는가, 그게 맞는가」**인데 우리 brief 의 3 초/15 초/60 초와 같은 물음이다(UD-6).

둘 다 **바이트 단위로 그대로** 넣고 `NOTICE` 에 출처·받은 날·「고친 곳 없음」을 적었다.

### 버린 것과 이유

- 나머지 스킬 다섯(`design-system` · `design-handoff` · `ux-copy` · `user-research` ·
  `research-synthesis`) — 우리 화면은 디자인 시스템 원본이 `ui/palette.json` 이고(UD-3),
  handoff 상대가 없고, 사용자 연구를 하지 않는다. **필요해지면 그때 같은 방법으로 가져온다.**
- MCP 9 개 — 위 표.
- 플러그인 자체 — 2 번 길이 없어서. 자동 갱신은 잃는다(`NOTICE` 로 대신한다).

### 되돌려야 하는 조건

- **팀 도구가 생기면**(Notion/Linear/Slack 을 실제로 쓰게 되면) 그 하나를 **커넥터로**
  켠다 — 플러그인 묶음이 아니라 필요한 것 하나만.
- 플러그인 MCP 를 끄는 설정 키가 생기면 1 번을 다시 본다.
- 복제한 스킬이 낡은 것을 모르고 쓰게 되면(상류가 크게 바뀌면) 플러그인으로 되돌린다.

### 2 패스 — 브리프에 대고 고친 것 (스킬의 핵심 절차: 「비슷한 brief 면 똑같이 나올 부분을 스스로 고쳐라」)

초안을 스킬의 클리셰 목록에 대 보았다. **1 번 항목과 거의 글자 단위로 같았다**:

| **따뜻한 크림 바탕** | 크림 자체가 그 기본값이다. 그리고 실제 기록지는 크림이 아니라 **더 밝고 덜 노랗다** | `paper` 를 **측정으로** 골랐다 — 아래 |

### A5 · A6 재판정 — 서체를 실은 뒤 (2026-09-19) `[측정]`

UD-9 0 번으로 서체가 실렸으므로(UF-6 해제) 글자가 전부인 두 후보를 **실제로 재서**
다시 판정했다. 위 표의 판정은 지우지 않는다 — **조건이 구체화된 것이지 뒤집힌 것이 아니다.**

**먼저 잰 것 — 3 m 가독을 px 로** (`02_benchmark` §10 으로 승급시켰다):
15.6" 에서 판독 35 px · **읽기 69 px** · 편안 139 px. 13.3" 면 읽기가 **81 px** 다.
**인치가 문서에 없어 이 조건이 판정 불가능이었다 — UF-10.** 아래는 15.6" 기준이고,
정해지기 전에는 가장 빡빡한 13.3" 를 가정한다.

#### A5 「재생 시계」 → **KEEP** (조건 셋)

| 잰 것 | 값 |
|---|---|
| A 원안 전체 줄 `재생 · 저장된 결과 · 50 mm/s · 혼합 −5 dB · 10.0 s 중 6.2 s` | 69 px 에서 **1709 px**(화면 89 %) · 81 px 에서 **2006 px → 넘친다** |
| 규약을 뺀 판 `재생 · 저장된 결과 · 혼합 −5 dB · 10.0 s 중 6.2 s` | 69 px **1374 px**(72 %) · 81 px **1613 px**(84 %) — **둘 다 들어간다** |
| 규약 줄을 따로 35 px 로 | **690 px** |
| 째깍임 떨림 (`10.0 s 중 6.2/8.8/1.1 s`) | **0.0 px** — Plex Sans 는 기본이 이미 tabular, Mono 도 0 |
| 대비 `ink-deck` on `deck` | **12.39:1** ✓ |

1. **규약을 상태 줄에서 뺀다.** `50 mm/s · 10 mm/mV · 대칸…` 은 3 m 대상이 아니다 —
   다가온 사람이 읽는 것이라 **35 px(판독) 아래 줄**로 내린다. 원안 그대로 한 줄에
   다 넣으면 13.3" 에서 **넘치고**, 15.6" 에서도 화면 89 % 를 먹어 **그 줄이 주연이 된다.**
2. **「재생」과 시계는 같은 줄·같은 크기.** A 의 원래 조건을 지킨다 — 「재생」이 작고
   째깍임만 크면 실시간 오독이 그대로 산다.
3. **떨림은 걱정하지 않아도 된다** — 잰 결과 0.0 px 다. `font-variant-numeric` 을
   굳이 켤 필요도 없다(Plex Sans 기본이 이미 고정폭 숫자다). 다만 **적어 두는 편이
   낫다** — 서체를 바꾸면 그 성질이 따라오지 않는다.

#### A6 「숫자 한 개」 → **TUNE 유지** (조건 둘이 **새로** 드러났다)

크기 주장은 **맞았다**: 180 px 는 15.6" 의 「편안」(139 px)을 넘는다. 폭 **864 px**(45 %).

- **조정 ①**: 가운데 정렬 금지. **소수점 기준 정렬**이나 부호·정수부 슬롯 고정으로
  자리를 잡는다. 「컷으로만 바뀐다」가 점프를 덜 거슬리게 하지만 없애지는 못한다.

  → **B5 「색은 만져야 온다」와 같은 결론에 독립적으로 닿았다.** 한쪽은 다크 팔레트가

### 갈림길

UD-10 은 Superdesign 을 **보류**하고 「9 기능 중 5 는 있고 2 는 의도된 공백, 2 는 범위 밖」이라
적었다. 그 판정 위에서 Director B 는 `frontend-design` 하나로 돌았고, 결과가 사용자에게
「과감하지 않다」로 평가됐다. 두 가지 중 무엇인가:

- **(가) 레퍼런스 금지가 상한이었다** — B 는 규약상 외부를 안 본다. 볼 것이 현행 화면뿐이라
  변주밖에 못 낸다.
- **(나) 대체가 대체가 아니었다** — UD-10 의 「우리 대응물」 열이 기능을 실제로는 안 덮었다.

이 둘은 배타가 아니다. **어느 쪽이 얼마나인지**가 갈림길이고, 답에 따라 UD-10 을 어디까지
되돌릴지가 달라진다.

### 새 단계 — **창의성·시각적 놀라움 줄세우기(VS)**, 검증기보다 앞에

사용자 지적 「해당 단계 설명이 부족했는데 있어야 할 것 같음, 기존 검증기는 UX 기반
검증기이니 다른 목적의 줄세우기」 `[대화]` 가 없던 단계를 하나 드러냈다.

**왜 검증기가 이 일을 못 하나**: 검증기 넷은 **계약 대조**다 — 파형·시간·단위·대비·모션은
통과/실패가 있다. 「더 놀랍다」에는 통과선이 없다. 통과선 없는 것을 통과/실패 도구로 재면
**안 걸린 것 전부가 동점**이 되고, 실제로 UD-11 에서 KEEP 이 5 개 나왔다 — 그중 무엇이 더
과감한지는 아무 데도 안 적혀 있다.

**VS 는 점수가 아니라 순서**이고, **동점을 금지**하며, **이웃한 두 개마다 왜 위인지 한 줄**을
쓴다. 규격은 `docs/ui/02_benchmark.md` §11 에 뒀다. 요지 넷:

1. **주제 교체 시험** — 후보 설명에서 「ECG·기록지·계측기」를 「주가·날씨·음악」으로 바꿔도
   문장이 성립하면 내린다. 성립 안 할수록 위.
2. **클리셰 대조** — `frontend-design` 클리셰 5 항 + UD-6·UD-9 가 이미 기각한 것.
3. **하루 뒤 한 문장** — 한 문장으로 말할 수 있나. 그 문장이 「깔끔하다/모던하다」면 0 점.
4. **대담함 개수** — 대담한 요소가 **1 개**일 때가 최고. 0 과 2 이상은 내린다(「대담함은 한 곳에」).

**순서**: 발산 A·B → **VS 줄세우기** → **사용자 정렬**(UO-5 가 빠뜨린 그 단계 — VS 순서가
사용자가 볼 자료다) → 사용자가 고른 1~2 를 **Superdesign 생성기로 시안** → 검증기 넷 →
KEEP/TUNE/REJECT → UD.

| 버린 것 | 왜 |

집계 수치만 간다.

### 되돌려야 하는 조건

- **Superdesign 을 붙여도 B 의 후보가 또 「현행 화면의 변주」뿐이면** — 원인은 도구가 아니라
  **브리프**다. 그때는 B 의 브리프에서 「무빌드 유지」·「`layout_b` 기준」을 빼고 백지에서 돌린다.
- **VS 순서와 검증기 판정이 거의 같게 나오면**(상위가 그대로 KEEP) VS 는 검증기의 중복이다 —
  단계를 뺀다. **두 라운드** 보고 판정한다.
- **크레딧이 드래프트에도 붙는 것으로 드러나면** 생성기 사용을 라운드당 1 회로 묶고
  그 수치를 여기 적는다.
- **로컬 실행이 사용자에게 부담이 되면** 생성기 없이 `extract-website` 결과(파일)만 받아
  오는 축소판으로 내린다 — 그것만으로도 (나) 의 절반은 풀린다.

라운드 ① 의 원인은 **둘이고 서로 독립**이다 — **도구가 0**(UD-12)과 **절차 결함**(UD-13).

| **E4** (겹쳐 쌓기) | **파형은 잘리면 「작다」로 읽힌다** — 글과 다르다. 가려지는 쪽이 R 피크면 **진폭 오독**이고 미감이 아니라 **데이터 거짓말**이다(LOW 구역) | 둘을 못 박아야 한다: ① 가려지는 쪽을 **기준선 아래**로 고정 ② 가려지는 양을 **0.5 mV 이내**로. 못 박으면 재 볼 값이 생긴다 |

**UF-12 를 받아 §14 를 고쳤다.** 「셋 다 `000`」은 **클라우드 세션의 사실**이었고 로컬에선
`200` 이다. 취소선으로 남기고 정정을 붙였다 — **틀린 사실이 지시문에 실리면 다음 실행자가
시도 자체를 안 한다.** 로컬 세션이 그대로 믿었으면 라운드 ④ 는 없었다.

### 이 결정이 못 답하는 것

**⑤ craft 칸은 절반만 찼다.** 갤러리 상위작의 wow 는 거의 다 **스크롤이 모는데 attract 에는
스크롤이 없다** — 허브의 한계가 아니라 **우리 구역의 성질**이다. `02_benchmark` §8.2.1 에
적었고, 더 원하면 **시간이 모는 전환**을 가진 소스(⑥ 전시·키오스크·사이니지)로 가야 한다.
**그 라운드를 지금 열지는 않는다** — 후보가 이미 **22 개**다(A 8 · B 5 · D 4 · E 5).
줄 세울 때가 됐다.

### 되돌려야 하는 조건

6. **「스크롤」이라는 말이 둘이 된다** — 재생 칩에 이미 **「스크롤」**(파형이 오른쪽에서 흐르는
   표시 모드, `layout_b.html:406`)이 있다. 페이지 스크롤로 넘어가는 화면에 같은 단어가 다른 뜻으로
   — 칩 이름을 바꿔야 한다.
7. **브라우저** `[문헌]` MDN BCD — `scroll-snap-type` 은 어디서나(Chrome 69 · Firefox 99 ·
   Safari 11). **`animation-timeline`(스크롤 구동)은 Chrome/Edge 115 · Safari 26, Firefox 는
   안정판에 없다.** 부스 노트북이 Edge 라(UF-9) 거기선 되지만 **없어도 동작하는 점진적 향상**이어야
   한다. `scrollsnapchange`(SnapEvent)는 Chromium 전용·실험적이라 **상태 판단에 쓰지 않는다** —
   IntersectionObserver 로.
8. **`live.html`(모드 A 실측) 앞에는 두지 않는다** — 재생 attract 가 실측 앞에 오면
   재생/실측이 섞인다. **모드 B 전용.**
