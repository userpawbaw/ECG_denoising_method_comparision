## UD-1. 시연 화면을 **디자인 시스템으로 다시 세운다** — 그리고 그 과정을 **도구·레퍼런스 비교 실험으로 설계한다**

> **이관**: 이 결정은 처음에 `docs/21_decisions.md` 에 **D-29** 로 적혔다. UI/UX
> 파트를 분리하면서 여기로 옮겼고, 원래 자리에는 이관 표시를 남겼다. 내용은
> 옮길 때 고치지 않았다 — 참조 경로만 새 위치로 바꿨다.


| | |
|---|---|
| 시점 | 사용자가 「demo 의 UI/UX 가 실망스럽다」며 외부 AI 대화(Figma·Mobbin·shadcn·Storybook·Playwright 파이프라인)를 가져와 재설계를 요청 |
| 상태 | **계획 확정 · 제작 전.** 계획서는 `docs/ui/01_system.md` |

### 갈림길 — **목적이 둘이다**

첫째는 화면을 고치는 것이다. 둘째가 이 결정의 성격을 정한다 —
**사용자의 목적에 「외부 도구와 외부 레퍼런스를 쓰면 결과물이 얼마나 달라지는가」를
보는 것이 포함돼 있다.** 산출 형태와 Figma 범위를 고른 이유도 거기에 있다.

그래서 이것은 단순한 구현 결정이 아니라 **비교 실험이고, D-28 의 기준이 그대로
걸린다 — 「측정할 수 없는 실험은 하지 않는다」(F-40).**

### 먼저 잰 것 — 화면 넷을 실제로 열었다 `[측정]`

headless Chromium 1440 폭. 아홉 가지가 나왔다(`docs/ui/01_system.md` 1 절).
무거운 넷:

- **같은 방법이 파일마다 다른 색이다.** `M_FE` 가 보고서에서 마젠타, 시연 시안에서
  황토, 본 화면에서 파랑이다. 본 화면은 방법 색이 없어 **네 칸이 전부 같은 파랑**이다.
- **`validate_palette.js` 가 저장소에 없다.** `docs/33` 이 그것으로 검증했다고
  적었는데 다른 세션의 도구였고 사라졌다 — **팔레트를 손대면 같은 자로 다시 잴
  수가 없다** (`docs/19_record_keeping.md` 6 절 위반).
- **타이포가 8~10 단계로 난립하고, `11·11.5·12·12.5 px` 넷은 눈으로 구분되지
  않는다.** 위계가 아니라 잡음이다.
- **`index.html`·`live.html` 의 `@media` 가 0 개다** — 반응형이 아예 없다.

뒤의 둘이 「미감적으로 별로」의 실체에 가장 가깝고, **실측이 알려주지 않는
종류**다. 이 과제의 결정이 거의 전부 자기 실측에서 나왔기 때문에 **관습과
미감에서 오는 것만 구조적으로 비어 있다.**

### 사라진 검증기를 찾았고, 돌려 보니 FAIL 이다 `[측정]`

`validate_palette.js` 는 **`dataviz` 스킬 안에 있었다** — 옵션 이름이 같고,
`docs/33` 이 기록한 `M_FE`↔`M04` ΔE 12.9 가 그대로 재현된다. 실제로 쓰이는
팔레트 넷을 전부 돌린 결과:

| 팔레트 | 판정 |
|---|---|
| 카드 3 색 | **ALL PASS** |
| **보고서·카드 7 색** (`make_slides` · `build_metric_cards`) | **FAIL** — `M02`↔`M01` 정상시야 12.3 |
| **시연 시안 4 색** (`mockup_expo`) | **FAIL** — 고전 황토↔입력 적갈 정상시야 14.0 |
| **시안 다크 4 색** | **FAIL** — 명도대 넷 다 이탈 |

**`docs/33` 이 검증한 것은 카드 3 색뿐이었다.** 그 결론은 카드에만 적용됐고,
**보고서 그림과 시연 시안은 검증을 통과한 적이 없다.** 시안의 FAIL 은 시연의
핵심 대비 — **입력 ↔ 고전 방법 출력이 색으로 안 갈린다**는 뜻이다.

검증기가 세션 밖 도구이므로 **같은 기준을 저장소 안에 다시 구현한다**(1 단계 첫
항목). 도구가 또 사라져도 자가 남아야 한다.

### 외부 스킬이 메운 것 — **축 1 의 첫 데이터 포인트**

`dataviz`(세션 내장)와 `ui-ux-pro-max`(MIT)로 같은 화면을 다시 훑어 **다섯이 더
나왔다** — 호버·툴팁 없음, 범례 없음(`index`), 표 뷰 없음, 시간축 라벨 없음,
`prefers-reduced-motion` 없음(스윕·스크롤을 돌리면서).

**전부 자기 실측만으로는 안 나오던 것들이다.** 그러므로 「외부 레퍼런스를
참고하면 결과가 달라지는가」의 답은 이미 부분적으로 나왔다 — **달라진다.**
다만 그 레퍼런스가 화면 DB 가 아니라 **규칙 묶음**이었다는 것이 이 판의 관찰이고,
그래서 **0 단계의 범위가 좁아졌다** — ECG 도메인 관습과 before/after 비교 UI 만
외부 조사로 남는다.

### 검토한 선택지

| | 안 | 판정 |
|---|---|---|
| 1 | 지금 화면을 손으로 다듬는다 | **✗** — 값이 네 파일에 흩어진 채라 같은 어긋남이 재발한다 |
| 2 | React + Vite + Storybook 전면 전환 | **✗** — `demo/index.html` 머리말(「시연 중에 실패할 계산이 없다」)과 D-18 을 철회해야 하고, 박람회 당일 새 실패 지점이 생긴다 |
| 3 | **무빌드 시연판 + 개발용 검증판 병행** | **✓ 채택** (사용자 판단) |
| 4 | Mobbin 구독 | **✗ 도구만 기각** — 아래 |

### 고른 것과 근거

**3 번.** 시연 산출물은 단일 HTML 로 두고 갤러리·스크린샷·검사만 개발 시점에
돈다. **실험 대상과 시연 산출물을 격리하는 것**이 이 선택의 핵심 값이다 —
도구 실험은 실패할 수 있는데, 실패가 박람회 당일 화면까지 번지면 실험 비용이
아니라 사고가 된다.

**대가 둘**:
- 두 벌 동기화. **시간 비용이 아니라 「조용한 어긋남」**이다 — `docs/33` 에서
  「세 안이 공유한다」고 적힌 채 B·C 가 첫 판 그대로였던 것이 이 종류다.
  **그래서 2 단계(화면을 여는 장치)가 선택이 아니라 전제다.**
- **비교 대상이 좁아졌다.** 무빌드를 고른 순간 shadcn 은 배제되고 Storybook 은
  빌드판 쪽에만 남는다. **이 판은 사실상 「Figma MCP 하나」를 잰다** — 결론을
  쓸 때 이 범위를 넘겨 말하지 않는다.

### 실험 설계 — 축 셋과 자

| 축 | 대조군 |
|---|---|
| **외부 레퍼런스 참고** | **있다** — 현 화면 전부가 「레퍼런스 없음」 판이다 |
| **검증 장치 유무** | **있다** — 지금까지 전부가 「장치 없음」 |
| **MCP 도구 사용** | **없다** — 3 단계에서 짝지어 만든다 |

**교란을 먼저 가른다.** 1·2 단계(팔레트 단일화 · 검증 장치)는 **MCP 없이도
된다.** 개선의 대부분이 거기서 나오므로, 그대로 두면 그 개선이 전부 「MCP 도입
효과」로 읽힌다 — F-9 가 경고한 사후 선택과 같은 구조다. 그래서 **1·2 단계는
공통 기반으로 깔고 3 단계에서만 경로를 둘로 가른다**(Figma 시안 ↔ 직접 HTML 시안,
같은 요구사항·같은 시점).

**자의 분해능**: n=1 이고 평가자가 한 명이라 **순위는 재고 크기는 못 잰다.**
사용자 합의 사항이며, 나중에 결론이 이 선을 넘지 않도록 적어 둔다.

### Figma 를 어디까지 쓰나 — **시안 보드이지 거울이 아니다**

사용자가 「디자인 시스템까지」를 택했다. 다만 Figma 를 「현재 화면을 반영하는
곳」으로 쓰면 **반드시 낡는다** — 코드를 고치는 순간 뒤처지고, 그 뒤에 사용자가
낡은 것을 보고 수정하게 된다(`docs/33` 의 Figma 판).

그래서 Figma 에 두는 것은 **「지금 화면」이 아니라 「제안 중인 대안」**이고,
현재 화면은 스크린샷으로 옆에 붙인다. 현재를 주장하지 않으므로 낡을 수가 없다.

토큰 값은 **양쪽 어디서 고쳐도 된다** — Variables ↔ `palette.json` 은 MCP 로
양방향 자동화가 된다. 처음 판은 「값의 원본은 저장소」라고만 적어 Figma 에서의
수정을 필요 이상으로 묶었는데, **실제 위험은 방향이 아니라 어긋남이 조용한
것**이다. 규칙을 「양쪽 다 고칠 수 있다. 단 어긋나면 드러난다」로 바꾸고, 대조
명령과 마지막 대조 시각으로 강제한다.

### 확정된 화면 규격 (사용자 판단)

| | 확정 |
|---|---|
| 표시 장치 | **노트북 1920×1080** (실 뷰포트 약 1920×910) |
| 최소 방어폭 | **1280×720** — 검사는 1280·1440·1920 세 구간을 돈다 |
| 테마 | **라이트·다크 둘 다.** 다크 스텝은 자동 반전이 아니라 **다시 고른다**(지금 것은 FAIL) |
| 조작 주체 | **관람객과 발표자 둘 다.** 기본을 관람객 기준(히트 타겟 ≥ 44 px · 자동 리셋)으로 잡고, 발표자용 상세는 「깊이」 뒤에 둔다 |

1920 이 기준이 되면서 U-3 의 성격이 바뀐다 — 파형 96 px 고정은 1920×910 에서
**화면의 다수를 비운다.** 반대로 여유가 생겨 표 뷰와 범례 자리도 함께 확보된다.

### 순서 — 앞 단계의 산출물이 있을 때만 다음으로

| 순 | 무엇 | 상태 |
|---:|---|---|
| **0** | **레퍼런스 분석** — 표시 규약 · 비교 UI · 대시보드 · **레이아웃/여백 · 타이포 · 반응형/상태/모션** | 대기 |
| 1 | 색 검증기 · 팔레트 단일 원본 · 토큰(타이포·간격 포함) 생성 | **검증기 ✅** (`scripts/validate_palette.py` — 참조 구현과 다섯 팔레트 전부 일치). 팔레트 원본은 다음 |
| 2 | **상태 갤러리 · 스크린샷 · 화면 검사** | 대기 |
| 3 | 레이아웃 재설계 — **경로 둘로 짝지어** | 대기 |
| 4 | 실패 상태 화면(끊김·lead-off)과 색각 이상 검증 | 대기 |

**3 번을 뒤에 둔 이유**: 바꾼 것이 나아졌는지 재는 자가 먼저 있어야 한다.
보기 좋아진 대신 대비가 무너지는 교환을 눈으로는 못 잡는다.

### 기각한 것과 이유

- **Mobbin/Refero 구독** — 모바일 앱 플로우 DB 이고 우리는 데스크톱 계측
  화면이다. **다만 도구를 기각한 것이 활동을 기각한 것은 아니다** — 이 문서의
  첫 판은 둘을 함께 버렸고 그건 오류였다. 벤치마킹은 공개 자료와
  `chrome --screenshot` 으로 되며 **0 단계로 승격했다.** U-8(타이포)·U-9(반응형)은
  그 단계가 아니면 나오지 않는다.
- **shadcn 컴포넌트 조달** — 우리 화면의 부품은 칩·슬라이더·캔버스 셋이고 이미
  있다. 못 만든 것은 **ECG 파형 패널**인데 registry 에 없다.
- **카드 세 안의 시각 언어를 하나로 통일** — 갈린 것이 **의도**다(`docs/33`:
  지나가는 사람 / 심사위원 / 다른 팀). 통일 대상은 본 화면 셋뿐이다.

## UD-2. 그림 색 **두 개를 ΔE 2 만큼 옮긴다** — 조합으로 재서 나온 최소 수정

| | |
|---|---|
| 시점 | UD-1 의 1 단계에서 검증기를 되찾은 직후, UF-1 로 진단을 정정하고 나서 |
| 상태 | **적용함** — `scripts/make_slides.py` · `scripts/build_metric_cards.py` |

### 갈림길

UF-1 로 실패가 **두 쌍**으로 좁혀졌다 — `M_FE`↔`M04` (정상시야 ΔE 12.9) 와
`M04`↔`M05` (13.7). 둘 다 상대가 `M04` 주황이다.

`M04` 를 옮기면 두 쌍이 한 번에 해결되지만, **`M04` 는 카드 3 안이 쓰는 슬롯 2**다
(`docs/33_card_design_samples.md`). 통과하고 있는 유일한 팔레트를 깨는 셈이라
**고정하고 상대 쪽을 옮겼다.**

### 검토한 선택지

| | 안 | 판정 |
|---|---|---|
| 1 | `M04` 를 옮긴다 | **✗** — 통과 중인 카드 3 색이 깨진다 |
| 2 | 팔레트 7 색을 전부 다시 고른다 | **✗** — UF-1 이 「과잉」이라고 판정한 바로 그 접근. 후보 탐색에서 **노랑이 갈색(ΔE 21.6)** 이 되는 답이 먼저 나왔다 |
| 3 | **`M_FE`·`M05` 를 통과하는 가장 가까운 값으로 스냅** | **✓ 채택** |
| 4 | 색을 그대로 두고 보조 부호(선 종류·질감)로 가른다 | **✗** — 정상시야 바닥 15 는 **보조 부호로 면제되지 않는다.** 색각이 정상인 사람도 구분을 못 하는 자리다 |

### 고른 것과 근거 `[측정]`

| 방법 | 전 | 후 | 이동 | 최악 정상시야 |
|---|---|---|---:|---|
| `M_FE` (front-end 단독) | `#e87ba4` | **`#e880b4`** | ΔE **2.2** | 12.9 → **15.1** |
| `M05` (Sameni EKS) | `#eda100` | **`#e4a824`** | ΔE **2.0** | 13.7 → **15.1** |

**ΔE 2 는 눈으로 거의 구분되지 않는다.** 분홍은 분홍으로, 노랑은 노랑으로 남으므로
보고서 그림의 인상이 바뀌지 않는다. 「통과하는 값 중 원래에서 가장 가까운 것」으로
고른 결과이고, 탐색 범위는 명도대·채도·대비를 먼저 통과한 3~4 만 색이었다.

적용 후 **슬라이드 세 조합과 카드 세 조합이 전부 ALL PASS** 다.

### 대가

`M_FE` 나 `M05` 가 들어간 그림은 **다시 그려야 한다** — `S4_noise_{d0,d1}` 와
`S6_safety` 둘이다(`scripts/make_slides.py --only S4 S6`). 색 값은 코드 한 곳에
있으므로 재생성으로 끝나고, **결론이나 수치는 건드리지 않는다.**

### 재생성이 아직 안 됐다 — 색 때문이 아니다 `[측정]`

`--only S4 S6` 을 돌렸더니 그림이 아니라 **체크포인트 적재**에서 멈췄다:

```
RuntimeError: Error(s) in loading state_dict for WaveletSubbandUNet:
  Missing key(s):    backbone.enc.0.0.c1.weight ...
  Unexpected key(s): backbone.enc.0.c1.weight ...
```

`M08` 의 저장된 가중치가 **현재 모델 구조와 키 모양이 다르다**(`enc.0.0` ↔ `enc.0`).
두 그림 다 `M08` 을 포함하므로 둘 다 막힌다.

**색 변경과 무관하다** — 색을 되돌린 상태(`git stash`)에서 같은 에러가 그대로
난다. 팔레트는 상수 딕셔너리이고 가중치 적재 경로를 지나지 않는다.

> **이것은 연구 파트 사안이다** — 모델 구조와 체크포인트의 정합 문제이고,
> UI 파트가 손댈 자리가 아니다. 여기서는 **그림이 아직 옛 색이라는 사실만**
> 기록해 둔다. 저장된 그림(`results/slides/`)은 tracked 산출물이므로
> 「새 것이 완성된 뒤에 교체한다」는 규칙대로 **그대로 두었다**(CLAUDE.md).

| | 상태 |
|---|---|
| 코드의 색 | ✅ 바뀜 (`make_slides.py` · `build_metric_cards.py`) |
| 검사 | ✅ 통과 — 조합 여섯이 전부 ALL PASS |
| 저장된 그림 | ⏳ **옛 색** — 체크포인트 정합이 풀린 뒤 재생성 |

### 검사

`tests/test_palette.py` 가 **팔레트를 코드에서 읽어** 조합별로 검증한다. 색을 또
바꾸면 검사가 자동으로 따라오고, 두 색이 원래에서 ΔE 5 이상 멀어지면 실패한다 —
「정체성을 지키면서 통과시킨다」는 이 결정의 요점을 고정한 것이다.

## UD-3. 팔레트 원본을 **저장소 루트 `ui/` 에 두고 CSS·Python 을 생성**한다

| | |
|---|---|
| 시점 | UD-1 1 단계 — 검증기(1)와 색 수정(UD-2)을 끝내고 값을 한 곳으로 모으면서 |
| 상태 | **적용함** — `ui/palette.json` · `scripts/build_tokens.py` |

### 갈림길

색이 네 파일에 각각 하드코딩돼 있었다. 방법 색만의 문제가 아니었다 `[측정]` —
역할 색도 갈려 있었다:

| | `make_slides.py` | `build_metric_cards.py` |
|---|---|---|
| `INK` | `#0b0b0b` | `#1b1b1b` |
| 보조 글자 | `INK2` `#52514e` | `MUTE` `#6b6b6b` |

**같은 저장소의 두 산출물이 같은 자리에서 다른 회색을 쓴다.** 두 그림이 나란히
놓이면 이것부터 어색해진다.

### 검토한 선택지

| | 어디에 원본을 두나 | 판정 |
|---|---|---|
| 1 | (기각) `demo/ui/palette.json` (처음 계획) | **✗** — 소비자가 둘이다. 보고서 그림(`scripts/`)이 **시연 디렉터리를 참조**하게 된다 |
| 2 | (기각) `ecgdn/palette.json` | **✗** — `ecgdn` 은 신호처리 패키지다. 색은 그 관심사가 아니다 |
| 3 | **저장소 루트 `ui/palette.json`** | **✓ 채택** — 두 소비자 어느 쪽에도 안 기울고, 이름이 곧 용도다 |

그리고 **생성물을 git 에 넣을 것인가**가 따로 갈렸다.

| | 안 | 판정 |
|---|---|---|
| A | 생성물을 git 에 넣지 않고 빌드 때 만든다 | **✗** — 시연 화면은 `file://` 로 열려야 한다(UD-1 3.1). 빌드 단계를 전제하면 그 설계가 깨진다 |
| B | **생성물을 git 에 넣고, 최신인지 검사한다** | **✓ 채택** |

### 고른 것과 근거

```
ui/palette.json                     ← 원본. 고칠 곳은 여기 하나
   ├→ demo/ui/tokens.css            (demo/*.html 이 읽는다)
   └→ scripts/_palette.py           (make_slides · build_metric_cards 가 읽는다)
```

B 의 대가는 「원본만 고치고 생성을 잊을 수 있다」이고, `build_tokens.py --check`
와 `tests/test_palette.py` 가 그것을 갚는다. **자동 생성 문서에 쓰는 것과 같은
장치다**(`docs/17_checklists.md` §4).

원본에는 색만 담지 않았다 — **검증 문턱값 · 조합을 어떻게 재는가(UF-1) ·
Figma 대조 시각 자리 · 확정된 뷰포트**가 함께 있다. 값과 「그 값을 어떻게
판정하나」가 떨어져 있으면 또 검증기가 사라진 것과 같은 일이 생긴다.

### 아직 담지 않은 것 **[미정]**

| 무엇 | 왜 |
|---|---|
| **타이포·간격 스케일** | 0 단계 R-D·R-E 가 아직이다. 근거 없이 단계를 정하면 지금 난립(8~10 단계)과 다를 바 없다. 현 상태는 `observed_px` 로 **관측만** 담아 뒀다 |
| **방법 색의 다크 스텝** | 자동 반전이 아니라 다크 표면 기준으로 골라야 한다. 계열 다크는 값이 있으나 **FAIL 상태 그대로** 담겨 있다 |
| **슬롯을 이름 있는 축으로 올릴지** | 같은 hex 가 front-end 모드·측정 함정 종류에도 쓰인다. 그 그림들에는 방법이 안 나와 충돌하지 않지만, 축이 이름을 갖는 편이 정확하다 |
| **`demo/*.html` 이 `tokens.css` 를 읽게 하는 것** | 3 단계(레이아웃 재설계)다. 화면에 방법 색을 붙이려면 **한 화면에 몇 개까지 그리나**가 먼저 정해져야 한다(01_system 8 절) |
