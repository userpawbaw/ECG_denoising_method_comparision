# 37. 시연 화면의 디자인 시스템 — 재설계 계획 `[검토 중]`

> 이 문서는 **제작 전 단계**다 — `docs/34_visual_plan.md` 와 같은 성격이다.
> 합의된 뒤에 만들고, 만든 뒤에 결과를 여기 반영한다.
>
> 출처: 사용자가 다른 AI 와 한 대화(Figma MCP · Mobbin · shadcn · Storybook ·
> Playwright 로 UI 파이프라인을 짜는 안)를 가져왔고, 그것을 **우리 화면을 실제로
> 열어 본 결과**에 비춰 판정한다. `docs/31_demo_design_review.md` 가 외부 시안을
> 다룬 것과 같은 방식이다.
>
> **이 재설계에는 목적이 둘이다** — 화면을 고치는 것과, **외부 도구·외부
> 레퍼런스가 결과물을 얼마나 바꾸는지 재는 것**이다. 4 절이 그 설계다.

---

## 0. 한 줄 결론

**진단은 「설계가 없다」가 아니다.** `docs/33_card_design_samples.md` 의 색 대비
검증 · 레인 렌더러 · 직접 라벨은 이미 제품 수준의 작업이다. 실망스러운 이유는
셋이고, 전부 **적용과 검증**의 문제다.

| | 무엇 | 왜 안 드러났나 |
|---|---|---|
| **A** | 그 규칙이 **본 화면(`demo/index.html`)에 적용되지 않았다** | 시안(`mockup_expo`)과 카드만 다듬었다 |
| **B** | 규칙의 **단일 출처가 없다** — 같은 방법이 파일마다 다른 색 | 색이 네 파일에 각각 하드코딩돼 있다 |
| **C** | **화면을 여는 장치가 없다** | 그림은 `tests/test_figure_text.py` 가 보는데 HTML 은 아무도 안 본다 |

C 가 A·B 를 몇 달간 숨겼다. `docs/33` 이 이미 같은 종류를 겪었다 —
「**문서가 코드보다 앞서 있었고, 화면을 열지 않으면 드러나지 않는다**」.

그리고 넷째가 있는데, 이건 성격이 다르다. **D: 우리 화면의 결정이 거의 전부
자기 실측에서 나왔다.** 그래서 **관습과 미감에서 오는 것만 구조적으로 비어
있다** — 6 절 0 단계가 그 자리다.

## 1. 측정 — 화면 넷을 실제로 열어서 본 것 `[측정]`

headless Chromium 1440 폭, `demo/` 의 네 화면. 스크린샷은 세션 산출물이라
저장소에 없다 — **재현 방법을 6.2 에 절차로 남긴다.**

| # | 무엇 | 근거 |
|---|---|---|
| **U-1** | 본 화면에 **방법 색이 없다** — `M_FE`·`M01`·`M04`·`M06` 네 칸이 전부 같은 파랑 | `demo/index.html` 의 `COLOR` 에 `input`·`clean`·`B01` 만 있고 나머지는 기본값 `#184f95` 로 떨어진다 |
| **U-2** | **같은 방법이 파일마다 다른 색** (2 절) | `scripts/make_slides.py` · `scripts/build_metric_cards.py` · `demo/mockup_expo.html` |
| **U-3** | 파형이 가장 중요한데 **가장 작다** — 칸 높이 96 px 고정, 1440×1400 에서 아래 300 px 가 빈다 | `demo/index.html` 의 `canvas{height:96px}` |
| **U-4** | 컨트롤 **일곱 그룹이 같은 무게**로 상단 25 % 를 먹는다 | 위계가 없어서 「무엇부터 만지나」가 안 읽힌다 |
| **U-5** | 증거 수치(`dB`·`cc`)가 **12 px 회색 본문**에 흐른다 | 화면에서 가장 중요한 숫자가 시각 순위 최하위다 |
| **U-6** | **실패 상태 화면이 설계되지 않았다** — 연결이 끊긴 `live.html` 은 파형 영역이 통째로 비고 설명문만 남는다 | **D-18 이 「끊김이 시연에서 실제로 일어난다」고 적은 바로 그 상태다** |
| **U-7** | 본 화면 셋이 **서로 다른 시각 언어**다 | 흰 바탕 시스템 폰트(`index`) / ECG 차트지 IBM Plex(`mockup_expo`) / 암전 형광(`cards/A`) |
| **U-8** | **타이포 스케일이 난립한다** `[측정]` — `index` 8 단계, `mockup_expo` 10 단계. 그중 `11 · 11.5 · 12 · 12.5 px` 넷은 **눈으로 구분되지 않는다** | 단계가 아니라 잡음이다. 위계를 만들려면 간격이 있어야 한다 |
| **U-9** | **반응형이 없다** `[측정]` — `index.html` · `live.html` 의 `@media` 가 **0 개**다 | 박람회 화면 크기가 노트북과 다르면 레이아웃이 그대로 깨진다 |

**U-7 은 절반이 의도다.** 카드 A·B·C 가 갈린 것은 주제의식이 다르기 때문이고
(`docs/33`: 지나가는 사람 / 심사위원 / 다른 팀), 그건 옳다. 문제는 **본 화면
셋끼리도 다른 것**이다. 이 셋은 같은 사람이 같은 자리에서 연달아 본다.

**U-8 · U-9 가 「미감적으로 별로」의 실체에 가장 가깝다.** 여백 리듬 · 타이포
단계 · 면 분할 같은 것은 실측이 알려주지 않는다. 그래서 이 과제가
구조적으로 비워 둔 자리이고, 0 단계(레퍼런스 분석)가 메울 곳이다.

## 2. 색 — **두 체계가 서로를 모른 채 병존한다** `[측정]`

| 방법 | `make_slides.py`·`build_metric_cards.py` | `demo/mockup_expo.html` | `demo/index.html` |
|---|---|---|---|
| `M_FE` | `#e87ba4` 마젠타 | `--classic` `#c07a1f` 황토 | `#184f95` |
| `M01` | `#2a78d6` 파랑 | `--classic` `#c07a1f` 황토 | `#184f95` |
| `M04` | `#eb6834` 주황 | `--classic` `#c07a1f` 황토 | `#184f95` |
| `M06` | `#184f95` 남색 | `--deep` `#184f95` 남색 | `#184f95` |
| `M08` | `#1baf7a` aqua | `--deep` `#184f95` 남색 | `#184f95` |
| `B01` | — | `--oracle` `#2f7d4f` 녹 | `#2f7d4f` 녹 |

**둘은 서로 다른 축을 인코딩한다.** 보고서·카드는 «방법 하나 = 색 하나»
(identity)고, 시연 시안은 «계열 하나 = 색 하나»(family: 고전·딥러닝·oracle)다.

**그리고 둘 다 근거가 있다.** `docs/33` 이 «색은 방법에 고정한다» 고 적은 것도,
`mockup_expo` 가 계열로 묶은 것도 같은 제약에서 나왔다 — 「**네 번째를 얹으면
정상시야 분리도가 무너진다**」. 카드는 방법을 셋으로 줄여 해결했고, 시연 화면은
여덟을 보여야 해서 계열로 묶을 수밖에 없었다.

> **즉 화면이 요구하는 방법 수가 색 체계를 강제한다.** 어느 한쪽이 틀린 게
> 아니라, **한 체계가 두 요구를 다 받도록 설계되지 않았다.**

### 2.1 제안 — 2 단 팔레트 (계열 = 색상, 방법 = 단계)

| 축 | 무엇이 정하나 |
|---|---|
| **색상(hue)** | **계열** — 입력 적갈 · 고전 황토 · 딥러닝 남색 · oracle 녹 · 참값 회색 |
| **단계(step)** | **계열 안의 방법** — `classic-1`=`M_FE`, `classic-2`=`M01`, `classic-3`=`M04` … |

셋만 그리면 단계가 충분히 벌어져 **방법색으로 읽히고**, 여덟을 그리면 계열이
먼저 읽힌다. **한 팔레트가 두 화면을 다 받는다.**

단계 값은 눈으로 고르지 않는다 — 2.2 의 검증기를 통과한 값만 쓴다.

### 2.2 `validate_palette.js` 가 **저장소에 없다** `[측정]`

`docs/33` 은 「`--pairs all` 로 검증했고」 「`validate_palette.js --mode light`
전 항목 PASS」라고 적는데, **그 파일이 저장소에 없다.** 다른 세션의 도구였고
사라졌다. 지금 팔레트를 바꾸면 **같은 자로 다시 잴 수가 없다.**

`docs/19_record_keeping.md` 6 절(측정 근거는 재현 가능하게)에 어긋난다. 그래서
**팔레트를 손대기 전에 검증기부터 저장소 안에 둔다** — 6.1 의 첫 항목이다.

## 3. 외부안 판정 — 채택 · 변형 · 기각

외부 대화는 `Figma MCP → Codex → React/shadcn → Storybook → Playwright → CI`
파이프라인을 제안했다. **방향은 옳고, 그대로 옮기면 이 과제의 제약 둘을 깬다.**

| 제안 | 판정 | 근거 |
|---|---|---|
| **Figma 로 디자인 시스템 구축** | **채택** | 사용자 판단. 무엇이 어디 사는지는 5 절 |
| **디자인 토큰을 의미 이름으로** | **채택** | 우리 문제(2 절)가 정확히 이것이다 |
| **ECG 전용 컴포넌트를 variant/state 로** | **채택** | `card_core.js` 의 `drawLane()` 이 이미 그 모양이다 — 개념이 아니라 **정리**의 문제 |
| **상용 제품 벤치마킹** | **채택 — 0 단계로 승격** | 6.0. **처음 판에서 뺐던 것을 되살렸다** |
| **상태별 갤러리** (Storybook 의 핵심) | **채택, 구현은 변형** | U-6·U-7 을 잡는 장치다. 6.2 |
| **브라우저 자동 검증** (Playwright) | **채택, 구현은 변형** | U-1~U-9 가 전부 «화면을 열면 5 초에 보이는 것»이었다 |
| **접근성 자동 검사** | **채택** | 색각 이상에서 고전↔딥러닝이 안 갈리면 시연의 주장이 전달되지 않는다 |
| **React + Vite 로 전면 전환** | **변형** | 3.1 |
| **shadcn 으로 부품 조달** | **보류** | 우리 화면의 부품은 칩·슬라이더·캔버스 셋이고 이미 있다. 못 만든 건 **ECG 파형 패널**인데 registry 에 없다 |
| **Mobbin 구독** | **기각 (도구만)** | 3.2 — **벤치마킹 활동은 남긴다** |

### 3.1 React 전환 — **시연용은 무빌드, 개발용은 빌드판** (사용자 확정)

`demo/index.html` 머리말이 설계 의도를 적어 뒀다 — 「**계산이 없다.** 시연 중에
실패할 계산이 없다는 것이 이 설계의 요점이다」, 「서버 없이 `file://` 로 열린다」.
**D-18** 도 같은 값을 골랐다.

전면 전환은 그 근거를 철회해야 하고, 박람회 당일에 **새 실패 지점**을 만든다.
그래서 **둘로 나눈다**: 시연 산출물은 `demo/*.html` 단일 HTML, 개발·검증판은
(계획) `demo/ui/` 와 `tests/`.

**대가를 적어 둔다**: 두 벌을 동기화해야 하고, **그 비용은 시간이 아니라
「조용한 어긋남」**이다(`docs/33` 선례). **그래서 6.2 의 검사가 선택이 아니라
전제다.**

### 3.2 Mobbin 은 기각, **벤치마킹은 남긴다**

Mobbin 은 모바일 앱 플로우 DB 다. 우리 화면은 1440 폭 데스크톱 계측 대시보드고,
흉내 낼 대상은 SaaS 앱이 아니라 **계측 장비와 차트지**다.

**그러나 도구를 기각한 것이 활동을 기각한 것은 아니다.** 처음 판의 이 문서는
둘을 함께 버렸는데 그건 오류였다 — 레퍼런스를 보고 공통점과 차이를 가르는
작업은 **도구와 무관하게, 공개 자료와 `chrome --screenshot` 으로 된다.**
6.0 이 그 단계이고, **U-8 · U-9 는 그 단계가 아니면 안 나온다.**

## 4. 이 재설계는 **비교 실험이기도 하다**

사용자의 목적에 「외부 도구와 외부 레퍼런스가 결과물을 얼마나 바꾸는지」가 있다.
그러면 `docs/21_decisions.md` D-28 의 기준이 그대로 걸린다 — **「측정할 수 없는
실험은 하지 않는다」(F-40).** 그래서 자와 대조군을 먼저 정한다.

### 4.1 축 셋, 그리고 대조군이 있는가

| 축 | 대조군 | 상태 |
|---|---|---|
| **외부 레퍼런스 참고** | **있다** — 현 화면 전부가 「레퍼런스 없음」 판이다 | 가장 깨끗하다 |
| **검증 장치 유무** | **있다** — 지금까지 전부가 「장치 없음」 | 자연 대조 |
| **MCP 도구 사용** | **없다** — 만들어야 한다 | 6.3 에서 짝지어 만든다 |

### 4.2 교란을 먼저 가른다

개선의 원인이 셋 섞여 있고, **그중 둘은 MCP 가 필요 없다.**

| 원인 | MCP 필요? |
|---|---|
| 팔레트 단일 출처 · 토큰화 (6.1) | 아니다 |
| 화면을 여는 검증 장치 (6.2) | 아니다 |
| Figma 로 레이아웃 설계 (6.3) | 그렇다 |

그래서 **6.1 · 6.2 는 공통 기반으로 깔고, 6.3 에서만 짝지어 비교한다.**
그러지 않으면 6.1·6.2 의 개선이 전부 「MCP 도입 효과」로 읽힌다 — F-9 가 경고한
사후 선택과 같은 구조다.

### 4.3 무빌드를 고른 순간 **비교 대상이 좁아졌다** — 기록해 둔다

| MCP | 이 구성에서 |
|---|---|
| Figma | ✓ |
| Playwright | ✓ — 다만 `chrome --screenshot` 으로 이미 진단이 됐다 (그 자체가 데이터 한 점이다) |
| Storybook | △ 빌드판 쪽에서만. 동기화 대상이 한 벌 더 는다 |
| shadcn | ✗ React registry 라 실질적으로 배제 |

**즉 이 판은 「MCP 생태계 전반」이 아니라 사실상 「Figma MCP 하나」를 잰다.**
결론을 쓸 때 이 범위를 넘겨 말하지 않는다.

### 4.4 자의 분해능 — **순위는 재고 크기는 못 잰다**

n=1 이고 평가자가 한 명이다. 「어느 쪽이 나은가」는 가려지지만 「얼마나」는
안 가려진다. **사용자 합의 사항이다** — 순위만 알면 충분하다는 것이 이 판의
요구다. 그래도 여기 적어 두는 것은, 나중에 결론이 이 선을 넘지 않게 하기
위해서다(F-40 이 「차이 없음」과 「못 잼」을 가른 것과 같은 이유).

재는 것: 6.2 의 검사가 잡는 결함 수 · 소요 시간 · **사용자가 직접 고친 횟수와
그 난이도** · 나란히 놓고 고른 선호.

## 5. 저장소와 Figma — 무엇이 어디에 사나

처음 판은 「값의 원본은 저장소」라고만 적었는데, 그 규칙은 **두 가지를 섞어서
말한 것**이라 Figma 에서의 수정을 필요 이상으로 묶는다. 갈라서 다시 적는다.

### 5.1 토큰 값과 레이아웃 구조는 다른 문제다

| | 토큰 값 (색 · 간격 · 타이포 단계) | 레이아웃 구조 (프레임 · 배치) |
|---|---|---|
| Figma 쪽 | Variables | Frame · Auto Layout |
| 저장소 쪽 | (계획) `demo/ui/palette.json` | `demo/*.html` 의 CSS |
| **옮기기** | **양방향 자동화가 된다** — MCP 로 읽고 쓴다 | **자동이 아니다** — 사람이 읽고 구현한다 |

**그래서 토큰은 양쪽 어디서 고쳐도 된다.** 사용자가 Figma 에서 색을 직접 바꾸는
것을 막을 이유가 없다. 실제 위험은 방향이 아니라 **어긋남이 조용한 것**이므로,
규칙을 이렇게 바꾼다:

> **양쪽 다 고칠 수 있다. 단 어긋나면 드러난다.**
> (계획) `scripts/sync_figma_tokens.py --check` 가 Figma Variables 와
> `palette.json` 을 대조해 차이를 보이고, 어느 쪽으로 맞출지는 사람이 정한다.
> `palette.json` 에 마지막 대조 시각을 적어 **얼마나 오래됐는지가 파일에서
> 읽히게** 한다.

### 5.2 Figma 는 **시안 보드이지 현재 화면의 거울이 아니다**

이것이 더 중요하다. Figma 를 「지금 화면을 그대로 반영하는 곳」으로 쓰면
**반드시 낡는다** — 내가 코드를 고치는 순간 Figma 가 뒤처지고, 그 뒤에 사용자가
Figma 를 열면 **낡은 것을 보고 수정하게 된다.** `docs/33` 이 겪은
「문서가 코드보다 앞섰다」의 Figma 판이다.

그래서 Figma 에 두는 것은 **「지금 화면」이 아니라 「제안 중인 대안」**이다.

| | 무엇이 있나 |
|---|---|
| Figma 캔버스 | 시안 · 대안 · 컴포넌트 정의. 확정되면 코드로 내려가고 프레임은 보관으로 넘긴다 |
| 옆에 붙이는 것 | **현재 화면 스크린샷** (6.2 가 만든다). 「지금 이것 ↔ 제안 저것」이 한 화면에 보인다 |
| 저장소 | 확정된 것 전부 |

**현재를 반영하는 척하지 않으므로 낡을 수가 없다.** `mockup_expo.html` 이 이미
그 역할(시안)을 했고, Figma 는 그 자리를 대체하되 **사용자가 직접 만질 수 있는**
시안 보드가 된다.

### 5.3 사용자가 수정을 요청할 때 — 경로별로 무엇이 일어나나

| 무엇을 하나 | 어디서 | 반영 | 걸리는 것 |
|---|---|---|---|
| 「이 색 더 진하게」 | 대화 | 내가 `palette.json` 을 고친다 | 없다 — 지금도 이 경로다 |
| 색 변수를 직접 수정 | Figma | `--check` 로 대조해 내려받는다 | 대조를 안 돌리면 조용히 어긋난다 |
| 프레임을 끌어 레이아웃 수정 | Figma | 내가 읽어서 HTML 로 구현한다 | **자동이 아니다.** 「읽어와서 반영해줘」가 필요하다 |
| 내가 코드에서 레이아웃 변경 | 저장소 | Figma 시안은 그대로 둔다 | 5.2 로 해결 — 시안은 현재를 주장하지 않는다 |

**세 번째 줄이 Figma 를 쓰는 진짜 이유다.** 레이아웃 대안 세 벌은 내가 HTML 로
빨리 만들 수 있어서 속도로는 Figma 가 이기지 않는다. **차별점은 그 결과물을
사용자가 직접 끌어서 고칠 수 있다는 것** — 말로 설명하지 않고. 코드 경로에는
그 지점이 없다. 4.4 가 「사용자가 직접 고친 횟수」를 재는 이유다.

## 6. 계획 — 0 단계부터 넷

각 단계는 **앞 단계의 산출물이 있을 때만** 시작한다.

### 6.0 0 단계 — 레퍼런스 분석 (**처음 판에서 빠졌던 것**)

기존 화면은 전부 자기 실측과 자기 판단으로만 만들었다. 그래서 **관습과 미감에서
오는 것만 비어 있다.** 근거 하나 `[측정]`:

| | 실제 심전도 표시 규약 | 우리 화면 |
|---|---|---|
| 가로 | 25 mm/s — 큰 칸 5 mm = **0.2 s**, 다섯 칸 = 1 s | `index`: 초 단위 세로선만. `mockup_expo`: **15 px 고정 격자** |
| 세로 | 10 mm/mV — 큰 칸 = **0.5 mV** | 없다. `ylim` 정규화뿐 |

**즉 우리 격자는 장식이다.** 폭이 바뀌면 한 칸이 뜻하는 시간이 같이 바뀌고,
임상의가 격자를 세어 RR·PR·QT 를 읽을 수 없다. 실험이 알려주지 않고 관습이
알려주는 종류다.

여섯 갈래로 본다. **뒤의 셋(R-D·R-E·R-F)이 「미감적으로 별로」에 직접
대응하고, 처음 판이 뺐던 부분이다.**

| 갈래 | 무엇을 보나 | 메우려는 빈자리 |
|---|---|---|
| **R-A 표시 규약** | 심전도 속도·이득·격자, 감시장치 관습(스윕 지우개 · lead-off · 알람 위계) | 격자가 장식이다 |
| **R-B 비교 UI** | before/after · 다중 계열 · 제거 성분 표시. **오디오 denoising 도구가 우리와 문제 구조가 같다** | 비교 레이아웃 · 제거 성분 뷰 |
| **R-C 관측 대시보드** | 컨트롤 배치, 요약→상세, 수치 표기 | U-4 · U-5 |
| **R-D 레이아웃·그리드·여백** | 기준 그리드, 콘텐츠 폭, 여백 리듬, 면 분할과 카드 위계, elevation | U-3 · U-4 — 1 px 선으로만 나누고 리듬이 없다 |
| **R-E 타이포·수치 표기** | 스케일 단계 수와 간격, 본문 ↔ 수치 ↔ 라벨 구분, tabular 정렬 | **U-8** — 8~10 단계 난립 |
| **R-F 반응형·상태·모션** | 폭 구간과 밀도 조절, 접힘 규칙, 빈·로딩·실패 화면, 전환 | **U-9**(`@media` 0 개) · U-6 |

`[근거 없음]` 으로 둔다」를 그대로 쓴다.

**칸을 하나 더 둔다.** `docs/31` 2 절의 경고가 여기 그대로 걸린다 — 상용 제품은
