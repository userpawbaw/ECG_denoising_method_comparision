### 2.1 `source: auto` 가 만든 함정 — 반드시 인지할 것

모든 학습·실험 config 가 `source: auto` 이고, `get_source("auto")` 는
**`data/raw/mitdb` 에 `.hea` 가 있으면 무조건 MIT-BIH 를 고른다.**

즉 **D1 데이터가 도착한 순간, 같은 config 를 같은 명령으로 돌려도 D0 가 아니라
D1 이 학습된다.** 실제로 확인했다 — `get_source('auto').kind == "mitdb"`,
train 기록이 `101, 106, 108, …` (MIT-BIH DS1).

이것은 **재현성 결함**이다. 같은 커밋 + 같은 config 가 작업 디렉터리 상태에 따라
다른 결과를 낸다. 산출물의 `manifest.json` 에 `source` 가 기록되므로 사후 판별은
가능하지만, 실행 전에는 알 수 없다.

→ 미해결 항목 M-1 (아래 5절).

### 3.3 실험 결과 — **D0 완결**

`results/d0/` 에 exp_a(173,712행) · exp_b(202,664) · exp_c(28,952) ·

`07_safety_probe_d0.md`, `10_loss_ablation_d0.md`.

주요 결과와 해석은 `91_report.md` 5장(전면 재작성)에 있다. 요약:

- **RQ1 의 답이 바뀌었다.** 15 dB 최고가 `M04`(7.79) → **`M08`(8.71)**.

`--source mitdb` 는 **TRAIN split** 을 쓴다. 이 스크립트들은 파라미터를 정하거나

(`qrs_dur_err_ms` 0.6397 등)이 어긋나지 않도록 확인했다.

#### D1 스모크에서 이미 보이는 신호 `[미확정]`

축소 설정(수십 초 × 2 record)으로 경로만 확인한 것이라 **결론이 아니다.**
다만 D0 와 방향이 크게 달라 P-7 에서 확인할 지점을 적어 둔다.

| 항목 | D0 (정식) | D1 스모크 |
|---|---|---|
| Sameni DoD (5 dB 개선) | +16.2 dB | **+1.53 dB** (기준 ≥8 미달) |
| SWT 튜닝 최적점 | `sigma=d2`, +11.4 dB | `sigma=d1`, tune **−0.15** / holdout +0.50 |

두 방법 모두 **합성에서 잘 되고 실데이터에서 안 되는** 쪽으로 나타난다.
Sameni 는 그럴 만한 이유가 있다 — D0 는 EKF 의 상태방정식과 **같은 생성 모델**
(McSharry ODE)로 만들어져 "모델이 정확히 맞는" 이상적 조건이기 때문이다.
사실이라면 F-8(합성이 딥러닝을 과대평가)의 대칭형, 즉 **합성이 모델 기반 방법을
과대평가**하는 사례가 된다. P-7 에서 정식 측정으로 확인해야 한다.

## 4. 확정된 설계 결정 (변경하려면 이 목록을 먼저 고칠 것)

1. **평가를 기법보다 먼저 만든다.** 지표의 분해능(`03_metric_floor.md`)을 먼저 재고,
   그 미만의 차이는 차이로 보고하지 않는다.
2. **상한선을 함께 그린다.** `B01`(wavelet 계열), `B02`(LTI 계열). 단
   **각자 자기 계열의 상한**이며 모든 방법의 상한이 아니다 (`M07` 은 저 SNR 에서 `B01` 을 넘는다).
3. **공정성 규약 5개** (`91_report.md` 4.2): 동일 입력 / SNR sweep 에서 잡음 실현 고정 /
   공통 front-end / guard band 5 s / 동일 R-peak 검출기.
4. **주 조건은 `frontend: true`**(실사용 시나리오), 부록이 `frontend: false`(알고리즘 본질).
5. **SNR 을 셋으로 분리**: `strict` / `scaled` / `gain_bias`.
6. **record 단위 inter-patient split** (DS1/DS2), 잡음도 시간축 disjoint.
7. **모든 결과표에 `M_FE`(front-end 단독)를 필수 행으로.** 규약은 선언이 아니라
   측정으로 확인한다 (F-10).

### M-4 상세 — 실제로 두 번 잃었다

1. `nohup … &` 로 띄운 학습이 turn 종료 시 프로세스 그룹째 정리됨.
   `results/.train.lock` 이 남아 있던 것이 증거 (정상 종료면 `trap EXIT` 이 지운다).
2. harness 추적 백그라운드로 다시 띄운 학습이 **컨테이너 재시작**으로 종료.

**해결(P-2)**: `Trainer.try_resume()` 과 `train.py --resume` 을 넣었다.
`last.pt` 에 optimizer·scaler 상태, LR 스케줄 위치(`step`), `best_epoch`,
history 를 함께 담는다. 가중치만 복원하는 것은 재개가 아니라 다른 학습이다.
러너는 `RESUME=0` 을 주지 않는 한 재개를 켠 채 돌고, 이미 목표 epoch 까지
끝난 학습은 건너뛴다.

**남는 한계**: 프로세스가 죽는 것 자체는 막지 못한다. 죽어도 잃는 것이
마지막 epoch 하나로 줄었을 뿐이다. LR 스케줄은 `epochs x len(loader)` 로
정규화되므로 재개할 때 `epochs` 를 바꾸면 남은 구간의 LR 곡선이 달라진다.

## 7. P-8 이후 남은 일

### 7.1 ~~O-10 · O-11~~ ✅ 해결 — 산출물 출처 추적

`ecgdn.utils` 에 두 가지를 넣었다.

- **`save_manifest(sources=[...])`** — 생성 코드 파일의 **내용 해시**를 산출물에
  남긴다. `scripts/check_freshness.py` 가 현재 파일과 대조해 낡은 산출물을 찾는다.
  git 커밋 해시로는 안 된다 (문서 커밋에 거짓 경보, 미커밋 수정은 누락).
- **`archive_run()`** — 현재 산출물을 `runs/{git}-{시각}/` 으로 보존한다.
  읽는 경로는 최상단 그대로여서 소비자 코드는 바뀌지 않았다.

`check_ckpts.py` 게이트가 실험 전에 학습 코드 변경을 확인한다 (F-9 를 실행
시점에 차단). 테스트 13건.

현재 상태: **최신 4 / 낡음 0 / 판정불가 29.** 판정불가는 이 변경 이전 산출물이고,
`sources` 가 없어 판정할 수 없다 — '최신' 으로 세지 않는다. 각 산출물이 다음에
재생성될 때 자동으로 추적에 들어온다.

> `exp_a/b/c`·`abl_loss` 는 재생성에 2.5 시간이 걸려 출처만을 위해 다시 돌리지
> 않았다. 다음 전체 재실행(예: 7.3 의 손실 재고정)에서 함께 들어온다.

### 7.2 ~~F-13~~ ✅ 해결 — 추정기의 천장을 실측했고, 그 결과 P-10 의 절차가 정해졌다

**가장 단순한 측정이 답을 줬다** — 잡음을 하나도 넣지 않은 신호에 추정기를 돌린다.
그 값이 추정기의 천장이다 (5 기록 중앙값, front-end 적용 후) `[측정]`.

| 추정기 | D0 (합성) | **D1 (실기록)** | 차이 |
|---|---|---|---|
| (A) beat 평균 잔차 | 19.6 | **11.9** | −7.7 |
| (B) half-sample | 19.8 | **12.8** | −7.0 |
| (C) 등전위 구간 | 16.8 | 15.6 | −1.2 |

**이 8 dB 가 F-13 의 −7.6 dB 편향과 일치한다** — F-13 이 지목한 원인(beat 마다
형태가 달라 그 변동이 잡음으로 계산된다)이 맞았고 크기까지 설명된다.

그리고 포화 경고 상수 `SNR_CEILING_DB = 22.0` 이 **D0 의 천장조차 넘는** 값이라
어느 축에서도 뜨지 않고 있었다 (F-18). 축별 실측값으로 바꿨다.

#### P-10 의 실측 절차가 이것으로 정해졌다

5.8.2 의 분기점 **13 dB** 가 (A),(B) 의 천장(11.9~12.8)에 놓여 있다.
그 둘로는 장비가 분기점의 어느 쪽인지 판정할 수 없다.

**(C) 등전위 추정기를 주로 쓴다** — 천장이 15.6 dB 라 13 dB 위에 여유가 있고,
D1 광대역 잡음 편향이 −1.6 dB 로 (A) 의 −5.8 보다 훨씬 작다.

단 (C)는 burst 잡음을 등전위 구간에서 놓쳐 +4~+7 dB 과대평가한다. 그래서
**`artifact_beat_frac` 으로 burst 여부를 먼저 판정**하고, burst 면 (A),(B) 를
함께 본다. 자세한 분기는 `docs/04_snr_estimator_calibration_d1.md` 의
'실기록에 적용할 때' 절.

### 7.3 손실 재고정 실험 (선택) — **후보가 L3 에서 L6 으로 바뀌었다**

5.8.9 — `L6`(clean 보존)이 `M06` 에서 양축 유의다(D0 +2.426, D1 +1.420).
20 dB 에서 `L3` 의 두 배를 내고, clean 보존 격차를 17.9 → 1.8 dB 로 좁힌다.
**기제까지 EXP-C 로 확인됐다.**

주 실험은 여전히 `L1` 로 고정돼 있고, **TEST 를 보고 바꾸면 사후 선택이다**
(F-9 · 5.8.7). 다시 재려면 **손실을 사전에 `L6` 으로 선언하고 주 실험 전체를
재실행**해야 한다 (학습 7종 + 실험 전부, 약 6 시간).

**이제는 할 만한 이유가 생겼다.** `L3` 때는 교차점이 13 → 15~16 dB 로 옮겨가는
정도였는데, `L6` 은 D0 에서 20 dB `M_FE` 대비 부호를 뒤집고(−1.60 → +3.04)
D1 에서도 격차의 74 % 를 메운다. **"딥러닝을 쓸 SNR 범위" 라는 이 보고서의
핵심 결론이 바뀔 수 있는 크기다.**

다만 D3(아두이노) 실측이 먼저다 — 장비 신호의 SNR 대역을 모르면 어느 구간을
겨냥해 재고정할지도 정할 수 없다.
