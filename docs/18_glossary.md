## 1. 신호와 참조

### `x_raw` — 원본 신호
데이터셋이 준 그대로의 신호. D0 는 합성 ECG, D1 은 MIT-BIH 기록.

### `x_ref` (문서에서 그냥 "참조" 또는 `x`) — 대역제한 참조
`x_ref = FrontEnd(x_raw)`. **평가의 정답이자 학습 타깃.**

왜 원본이 아닌가: MIT-BIH 는 clean 이 아니라 이미 기저선 변동을 담고 있다.
원본을 정답으로 두면 front-end 가 그 성분을 지울수록 정답에서 **멀어져**
SNR 이 떨어진다 (→ F-12). 그래서 과제 목표를 **"0.5~100 Hz 대역의 ECG 복원"**
으로 명시하고 참조도 그 대역으로 맞췄다.

잡음은 여전히 **`x_raw` 에 섞는다** — 실제 취득계는 대역제한 전 신호를 본다.

### `y` — 잡음이 섞인 입력
`y = x_raw + α·n`, `α` 는 목표 SNR 을 맞추는 스칼라.

### front-end (`M_FE`)
전 방법 공통 전처리: **HPF 0.5 Hz + LPF 100 Hz + 조건부 60 Hz notch**
(zero-phase `filtfilt`). 방법으로도 등록돼 있어 **모든 결과표의 기준선** 역할을
한다 — 각 방법의 이득 중 얼마가 이 공통 전처리에서 온 것인지 표에서 바로
읽히게 하기 위해서다 (→ F-10).

### 데이터축 D0 / D1 / D2 / D3
| | 내용 |
|---|---|
| **D0** | 합성 ECG (McSharry ODE). 파이프라인 검증용 |
| **D1** | MIT-BIH Arrhythmia + NSTDB 실잡음 |
| D2 | MIT-BIH clean + Arduino 잡음 (device adaptation) |
| D3 | Arduino 실측 |

산출물 경로는 `results/d0/`, `results/d1/` 로 분리한다 (→ D-2).

## 2. SNR 계열 — 왜 셋으로 나눴는가

denoising 출력 `x̂` 을 참조 `x` 와 비교할 때, **"파형이 맞는가"** 와
**"크기가 맞는가"** 는 다른 질문이다. 하나의 SNR 로 합치면 둘이 뒤섞인다.
그래서 셋으로 분리한다. **모든 계산은 양쪽의 평균을 먼저 뺀다**(DC 규약).

### `snr_out_strict` — 있는 그대로의 출력 SNR

$$\text{SNR}_\text{strict} = 10\log_{10}\frac{\lVert x\rVert^2}{\lVert \hat x - x\rVert^2}$$

크기가 틀리면 그대로 벌점을 받는다.

### `snr_out_scaled` — 최적 이득 보정 후 SNR

먼저 오차를 최소화하는 스칼라 `α*` 를 구하고(아래 `gain_bias`), 그것을 곱한 뒤 잰다.

$$\text{SNR}_\text{scaled} = 10\log_{10}\frac{\lVert x\rVert^2}{\lVert \alpha^* \hat x - x\rVert^2}$$

**"크기를 맞춰준다면 파형 구조 자체는 맞는가"** 를 잰다.
크기 오차에 면죄부를 주므로 항상 `strict` 이상이다.

> 본 프로젝트의 **주 지표는 `snr_imp_scaled`** 다. 크기 오차는 `gain_bias` 로
> 따로 보고하므로 이중 벌점을 피한다.

### `gain_bias` (α*) — 최적 이득

$$\alpha^* = \arg\min_\alpha \lVert \alpha\hat x - x\rVert^2 = \frac{\langle x,\hat x\rangle}{\langle \hat x,\hat x\rangle}$$

**1보다 크면 출력이 참값보다 작다**(그래서 키워야 한다)는 뜻이다.

**해석 주의**: `α*` 는 스칼라 Wiener 이득이라 **입력 SNR 에 강하게 종속**된다.
무처리(`M00`)조차 −5 dB 에서 0.241, 20 dB 에서 0.990 이 나온다. 잡음이 신호보다
크면 관측을 축소하는 것이 오차를 줄이기 때문이다. **전체 평균으로 방법 특성을
논하면 안 되고 SNR 별로만 읽어야 한다.**

### `snr_imp_*` — 개선폭
$$\text{snr\_imp} = \text{SNR}_\text{out} - \text{SNR}_\text{in}$$

`SNR_in` 은 **모델/방법이 실제로 받은 입력** 기준이다. 따라서 front-end 를
적용한 뒤 학습한 딥러닝의 `snr_imp` 는 **front-end 가 한 일을 뺀 순수 추가
기여**다. front-end 없던 시절의 값과 직접 비교하면 안 된다.

## 3. 형태(morphology) 지표

### `beat_cc` — beat template 상관
모든 beat 를 R-peak 로 정렬해 평균한 **template** 을 참조와 출력에서 각각 만들고,
둘의 Pearson 상관을 낸다.

$$\text{beat\_cc} = \frac{\langle t_\text{ref}-\bar t_\text{ref},\; t_\text{hat}-\bar t_\text{hat}\rangle}{\lVert t_\text{ref}-\bar t_\text{ref}\rVert\,\lVert t_\text{hat}-\bar t_\text{hat}\rVert}$$

범위 −1~1, **1이 완벽**. 평균 template 이므로 개별 beat 손상은 가려질 수 있어
`beat_cc_median`(beat 단위 상관의 중앙값)을 함께 본다.

### `r_amp_err_pct` — R-peak 진폭 상대오차 [%]

$$\text{r\_amp\_err\_pct} = 100 \times \operatorname{mean}_i\frac{\lvert \hat a_i - a_i\rvert}{\lvert a_i\rvert}$$

`a_i` 는 i번째 beat 의 R-peak 진폭. **0이 완벽**이고 상한은 없다.

**값 읽는 법**: 100 % 는 "진폭이 평균적으로 참값만큼 어긋남", 242 % 는
"평균 2.42배 어긋남". 수학적으로 큰 값이 불가능한 것은 아니지만,
**거의 완벽한 출력을 넣는 floor 측정에서 242 %가 나오면 측정이 잘못된 것**이다
(→ F-12 후속 정정).

### `qrs_dur_err_ms` — QRS 폭 오차 [ms]
참조와 출력 각각에서 QRS 시작·끝을 delineation 으로 찾아 폭을 재고, 그 차이의
평균. **0이 완벽.**

**한계**: delineation 자체가 불안정하면 이 지표의 바닥값이 커진다.
실제로 D1 의 floor 는 **28.07 ms** 로 D0(0.64 ms)의 44배다 — 실데이터에서
이 지표는 사실상 판별력이 없다.

## 4. 하류 과제 지표 (R-peak 검출)

denoising 출력에 **동일한 검출기**(`wfdb.xqrs`)를 돌려 참조의 R-peak 와 매칭한다.
매칭 허용 오차는 ±150 ms.

| | 정의 | 뜻 |
|---|---|---|
| `Se` (민감도) | TP / (TP + FN) | **놓치지 않았는가** |
| `PPV` (양성예측도) | TP / (TP + FP) | **없는 것을 만들지 않았는가** |
| `rpeak_mae_ms` | 매칭된 peak 의 \|시간오차\| 평균 | 타이밍 **산포** |
| `rpeak_bias_ms` | 부호 있는 시간오차 평균 | 타이밍 **편향** |

**`rpeak_mae_ms` 만 보면 안 되는 이유**: 이 지표는 **매칭된 peak 만** 본다.
절반을 놓쳐도 남은 것의 타이밍이 정확하면 작게 나온다. 그래서 `Se`/`PPV` 를
주 지표로 올렸다 (→ D-7).

**`mae` 와 `bias` 는 다르다**: 실측에서 `rpeak_mae_ms` 8.72 ms 인데
`rpeak_bias_ms` 는 1.20 ms 였다. 8.72 는 체계적 밀림이 아니라 **무작위 산포**이고,
편향은 빼서 교정할 수 있지만 산포는 뺄 수 없다.

## 5. metric floor — 지표 자체의 분해능

**질문**: "이상적인 출력을 넣었을 때 이 지표는 얼마나 흔들리는가?"

**측정법**: 참조 `x` 에 **40 dB AWGN**(거의 무시할 수준의 교란)을 여러 seed 로
더한 것을 '출력' 으로 넣고, 각 지표가 이상값에서 얼마나 벗어나는지 잰다.
`floor_p95` 는 그 편차의 95 퍼센타일.

**쓰는 법**: **두 방법의 차이가 floor 미만이면 차이로 보고하지 않는다.**

**주의 — 잡음을 어디에 섞는가**: floor 측정에서는 **참조 `x` 자체에** 섞어야
한다. 원본 `x_raw` 에 섞으면 front-end 차이(D1 에서 9.3 dB)가 통째로 들어가
floor 가 부풀려진다. 파이프라인을 모사하는 다른 측정(SWT 튜닝 등)과 반대다
(→ F-12 후속 정정).

## 6. 파라미터 탐색 — tune 과 holdout

파라미터를 고를 때 **고르는 데 쓴 데이터로 성능을 보고하면** 그 값은
낙관적으로 편향된다(그 데이터에 맞춰 골랐으므로). 그래서 둘로 나눈다.

| | 역할 |
|---|---|
| **tune** | 파라미터 탐색에 쓰는 기록/seed. 여기서 최적점을 고른다 |
| **holdout** | 탐색에 **전혀 쓰지 않고** 검증만 하는 기록/seed |

둘 다 **TRAIN split 안에서** 나눈다. TEST 에서 파라미터를 고르면 그 선택이
평가에 새어 들어간다.

### 두 값의 관계로 무엇을 판정하는가

| 관측 | **우선적으로 의심할 것** |
|---|---|
| tune 높음 · holdout **낮음** | **과적합** 또는 tune 데이터 특화 |
| tune ≈ holdout, 둘 다 **높음** | 현재 설정에서 일반화되는 것으로 보인다 |
| tune ≈ holdout, 둘 다 **낮음** | 특정 파라미터 하나의 선택 실패만으로는 설명하기 어렵다. **탐색 범위·목적함수·참조 정의·평가 설정**을 점검한다 |

> **주의**: 세 번째 관측만으로 *탐색 공간 전체의 우열을 확정할 수는 없다.*
> 전체 후보를 전수 평가한 경우가 아니라면, 이것은 "단순한 파라미터 선택 실패로
> 설명하기 어렵다" 는 **진단의 근거**로만 쓴다. 확정하려면 탐색이 실제로 전수였는지,
> 그리고 각 후보의 값이 기록에 남아 있는지 확인해야 한다.

세 번째가 F-12 의 발단이었다. D1 에서 tune −0.49 / holdout −0.55 로 **둘 다
음수이면서 일치**했다. 과적합이면 tune 만 좋아야 하는데 그렇지 않았으므로,
"파라미터를 잘못 골랐다" 로는 설명되지 않았다. 실제 원인은 탐색 바깥,
**참조 정의**에 있었다.

### `textbook-baseline`
튜닝하지 않은 교과서 기본 설정(uniform k, soft threshold, QRS 보호 없음)의 성능.
튜닝이 실제로 이득을 냈는지 보는 대조군이다.

## 7. SWT thresholding 파라미터

정지 웨이블릿 변환(SWT)으로 신호를 레벨별 세부계수 `D1..D5` 와 근사계수 `A5` 로
나눈 뒤, 세부계수에 threshold 를 적용해 잡음을 줄인다.

| 파라미터 | 뜻 |
|---|---|
| `sigma_source` | 잡음 표준편차 σ 를 **어느 레벨에서** 추정할지 (`d1`=최고주파, `d2`, `min12`, `level`=레벨별) |
| `k` | 레벨별 threshold 배수. `threshold_j = k_j · σ`. **클수록 많이 지운다** |
| `mode` | `soft`(임계 초과분만 남김) / `hard`(임계 미만을 0으로) / `garrote`(둘의 절충) |
| `protect_qrs` | QRS 구간의 계수를 덜 지울지 여부 |

**`sigma_source` 가 중요한 이유**: 레벨별 MAD 로 σ 를 추정하면, ECG 가 계수를
지배하는 저주파 레벨(D3 이상)에서 σ 를 2~5배 과대추정해 QRS 를 잘라낸다
(→ F-5).

**근사계수 `A5` 는 thresholding 하지 않는다.** 그래서 `A5` 에 실려 있는
기저선 변동은 SWT 로 **원리적으로 제거할 수 없다** — oracle 조차 그렇다 (→ F-11).

## 8. oracle 벤치마크

| | 정의 | 무엇의 상한인가 |
|---|---|---|
| `B01` | 참값을 알고 **각 wavelet 계수를 최적으로 keep/kill** | **wavelet thresholding 계열**의 상한 |
| `B02` | 참값을 알고 최적 **LTI Wiener 필터**를 구성 | **선형 시불변 필터** 계열의 상한 |

**"모든 방법의 상한"이 아니다.** 실제로 `M07` 은 저 SNR 에서 `B01` 을 넘는다.
oracle 을 넘는다는 사실 자체가 **그 oracle 이 그 방법의 상한이 아니라는 증거**다.
따라서 "oracle 대비 부족분"은 같은 계열(`M03`/`M04`)에만 쓸 수 있다 (→ D-6).

또한 **oracle 도 front-end 를 통과한다.** 그래서 oracle 의 왜곡 하한은
front-end 의 천장과 같다 (→ F-11).

## 9. 통계

### paired Wilcoxon signed-rank
각 record 에서 두 방법의 값을 **짝지어** 차이의 부호와 순위로 검정한다.
정규성을 가정하지 않고, record 간 난이도 차이가 상쇄된다.
단위는 **record**(n=22)이지 구간이 아니다 — 같은 record 의 구간들은 독립이 아니다.

### Holm 보정
여러 방법을 한 baseline 과 비교하면 우연히 유의해 보이는 것이 나온다.
Holm 은 p 값을 정렬해 단계적으로 기준을 엄격하게 만들어 이를 보정한다.
표의 `p_holm` 이 보정 후 값이다.

### rank-biserial `effect r`
효과 크기. **+1 이면 모든 record 에서 이겼다**, −1 이면 모두 졌다는 뜻.
p 값은 "차이가 있는가"만 답하고 **크기는 답하지 않으므로** 함께 본다.

`M08` 의 `r = 1.000` 은 22개 record **전부에서** `M01` 을 이겼다는 뜻이다.

### `n.s.` (not significant)
Holm 보정 후 p ≥ 0.05. **"차이가 없다"가 아니라 "차이가 있다고 말할 근거가
부족하다"** 는 뜻이다.

## 10. 안전성 프로브 지표

### `halluc_energy` — 없는 파형을 만들어냈는가
참조에서 한 구간(1 beat 또는 3 s)을 **등전위선으로 지우고** 잡음을 덮은 뒤,
출력이 그 자리에 만들어낸 에너지를 원래 그 구간이 갖고 있던 에너지로 나눈 값.

$$\text{halluc\_energy} = \frac{\lVert \hat x_{\text{삭제구간}}\rVert^2}{\lVert x_{\text{원래}}\rVert^2}$$

**낮을수록 안전.** 1에 가까우면 사라진 beat 를 그대로 복원(=생성)했다는 뜻이다.

**해석 주의**: 잡음이 그대로 남아도 이 값은 올라간다. 무처리(`M00`)가 높은 것은
생성이 아니라 잡음이 남아서다. 따라서 **잡음 제거량(EXP-A)과 함께** 읽어야 한다.

### `V − N` — 부정맥 편향
부정맥 beat(V)와 정상 beat(N)의 `beat_cc` 차. **크게 음수면 그 방법이 정상 beat 에
편향되어 부정맥을 훼손**한다는 뜻이다.
