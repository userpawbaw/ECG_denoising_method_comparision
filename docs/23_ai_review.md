# 23. AI 협업 검토 기록 (R)

> **이 문서가 F/D/O 와 다른 점.** F/D/O 는 **프로젝트에서 무슨 일이 있었는가**를
> 기록한다. R 은 **AI 와 함께 일하면서 무엇이 어떻게 어긋났고, 다음에 AI 를 쓸 때
> 무엇을 요구해야 하는가**를 기록한다.
>
> **판별 질문**: "이건 이 프로젝트에 관한 교훈인가, **AI 를 쓰는 방법**에 관한
> 교훈인가?" 후자면 R 이다.
>
> **범위를 좁게 유지한다.** 실험 내용은 F 에 있고 R 은 그것을 **참조만** 한다.
> R 에 실험 서술을 복사하면 두 문서가 어긋나기 시작하고, 고칠 때 두 곳을
> 고쳐야 한다. R 이 답할 것은 오직 **"그래서 AI 에게 무엇을 요구해야 하는가"** 다.

## 항목 형식

```markdown
## R-nn. 한 줄 요약

| | |
|---|---|
| 대상 | 어떤 AI 산출물인가 |
| 처리 | 채택 / 부분 채택 / 폐기 / 보류 |
| 연결 | F-· D-· O- 중 관련 항목 |

### AI 가 내놓은 것
### 사람이 문제 삼은 것
### 검증 방법과 결과
### 재사용 규칙   ← 이 항목이 R 의 존재 이유다
```

**`재사용 규칙` 이 없으면 R 로 남길 가치가 없다.** 그냥 F 나 O 다.

## R-1. AI 가 기록을 보완하라는 요구를 받고 없던 판단 과정을 지어냈다

| | |
|---|---|
| 대상 | `20_findings.md` F-1~F-9 의 "먼저 의심한 것" 절 |
| 처리 | **폐기 후 재작성** |
| 연결 | 규약 `19_record_keeping.md` 8절 |

### AI 가 내놓은 것

기록 규약에 "먼저 의심한 것" 을 필수 항목으로 넣은 직후, 자체 점검에서 F-1~F-9
대부분이 그 항목을 채우지 못한다는 결과가 나왔다. AI(=이 세션의 Claude)는
그것을 "보완" 하면서 다음 같은 서술을 채워 넣었다.

- F-1 "처음엔 학습 불안정(발산, LR 과다)을 의심했다"
- F-2 "PVC 커널의 파형 자체가 필터를 힘들게 하는 것으로 생각했다"
- F-3 "추정기 공식을 의심했다. 공식을 다시 유도해도 맞았다"
- F-4 "EXP-C 측정 자체가 틀렸나를 먼저 봤다"

전부 그럴듯하고, 실제로 그렇게 판단했을 법하다.

### 사람이 문제 삼은 것

> "필수 4요소를 억지로 채우려고 하면 없는 파트를 채우느라 없던 정보를
> 만들어내는 할루시네이션 위험이 있을 것 같은데."

### 검증 방법과 결과

세션 전사에서 해당 표현을 검색했다. 결과: **F-1·F-2·F-3·F-4 의 위 서술은
전사에 근거가 없었다.** `[대화]`

검증 과정에서 **검증 방법 자체의 함정**도 드러났다. 전사에는 AI 가 방금 작성한
문서 내용도 포함되므로, 검색이 **자기가 쓴 문장을 근거로 잡는다**(F-2 의
"파형을 그려" 가 그렇게 잡혔다). 자기참조를 걸러야 검증이 성립한다.

### 처리

네 항목을 **`기록 없음`** 으로 되돌리고, 남아 있는 증거만 근거 등급과 함께
다시 적었다. 근거 등급 체계(`[측정]`/`[로그]`/`[커밋]`/`[대화]`/`[코드]`/
`[문헌]`/`[추론]`/`[재구성]`)와 "빈칸이 허위보다 낫다" 는 규칙을 규약에 넣었다.

### 재사용 규칙

1. **필수 항목이 비어 있으면 채우라고 요구하지 않는다.** "채울 수 있으면 채우고,
   근거가 없으면 `기록 없음` 이라고 적어라" 로 요구한다.
2. **과거의 판단 과정을 복원하게 할 때는 근거를 함께 요구한다.**
   "무엇을 먼저 의심했는가" 는 코드에 흔적이 남지 않으므로, 전사·로그에
   없으면 복원할 수 없는 것이 정상이다.
3. **AI 가 자기 산출물을 검증하게 할 때 자기참조를 배제하도록 지시한다.**
   "네가 방금 쓴 문서는 근거에서 제외하고 확인하라."

## R-2. AI 가 "자세히 풀어 쓰라" 는 요구를 받고 논리를 근거 너머로 밀어붙였다

| | |
|---|---|
| 대상 | `20_findings.md` F-12 의 tune/holdout 해석 |
| 처리 | **부분 채택** (설명은 유지, 결론은 약화) |
| 연결 | F-12, `18_glossary.md` 6절 |

### AI 가 내놓은 것

"배경지식 없는 독자도 따라올 수 있게 풀어 쓰라" 는 요구를 받고 F-12 의 발단을
확장하면서, 다음 문장을 넣었다.

> "탐색이 최선을 다해 고른 파라미터조차 tune 에서 음수였다. 이는 후보 조합
> 어디에도 양수가 없었다는 뜻이고, **탐색 공간 전체가 음수** 라는 결론이 된다."

### 사람이 문제 삼은 것

외부 검토에서 이 문장이 **관측이 뒷받침하는 범위를 넘는다**는 지적이 나왔다.
탐색이 고른 최적 후보가 음수라는 사실만으로 모든 조합이 음수임이 증명되지는
않는다는 것이다.

### 검증 방법과 결과

탐색 구조를 코드에서 확인했다 `[코드]`.

- 1단계: `sigma_source`(4) × `mode`(3) × `protect_qrs`(2) = **24 조합 전수**
- 2단계: `k` 벡터는 **좌표탐색** — 전수가 아니다

즉 지적이 맞다. 그리고 확인 과정에서 더 나쁜 사실이 나왔다 — **당시 24 조합의
개별 값을 지금 확인할 수 없다.** 참조를 고친 뒤 재실행하면서 `search.csv` 가
덮어써졌기 때문이다 `[측정]`. 로그에는 각 단계의 최선만 남아 있다 `[로그]`.
(→ O-10)

### 처리

F-12 의 결론을 "탐색이 도달한 최선이 음수였다" 까지로 약화하고, 무엇을 증명하지
못하는지를 명시했다. 같은 과장이 있던 `18_glossary.md` 의 진단표도
"우선적으로 의심할 것" 으로 바꿨다 — glossary 는 개념의 canonical source 라
더 조심해야 한다.

### 재사용 규칙

1. **"자세히 설명하라" 는 요구는 "더 강하게 주장하라" 가 아니다.** 설명을
   확장할 때 결론의 강도는 그대로 두어야 한다. AI 에게 요구할 때 이것을
   명시한다: *"설명은 늘리되 주장의 범위는 늘리지 마라."*
2. **"전체", "모든", "항상", "불가능" 같은 단어가 나오면 근거를 되묻는다.**
   이번 두 사례가 모두 그런 단어였다("탐색 공간 **전체**", "지표 정의상
   **불가능**").
3. **탐색·최적화 결과를 해석할 때는 탐색이 전수였는지 먼저 확인한다.**

## R-3. AI 가 원칙을 일괄 적용해 목적이 다른 측정을 망가뜨렸다

| | |
|---|---|
| 대상 | F-12 조치의 보조 스크립트 4개 일괄 수정 |
| 처리 | **부분 폐기** (3개 유지, 1개 되돌림) |
| 연결 | F-12 후속 정정, O-10 |

### AI 가 내놓은 것

F-12 에서 "잡음은 원본에 섞고 평가는 대역제한 참조로" 라는 규칙을 정한 뒤,
그것을 **네 보조 스크립트에 똑같이** 적용했다.

### 무엇이 문제였나

`measure_metric_floor` 에는 그 규칙이 틀렸다. 이 측정의 질문은 "이상적인 출력을
넣었을 때 지표가 얼마나 흔들리는가" 이므로 **출력이 참조와 같은 대역에 있어야**
한다. 원본에 섞으면 front-end 차이가 통째로 들어가 floor 가 부풀려진다.

### 검증 방법과 결과

이상을 알아챈 신호는 **`r_amp_err_pct` floor 가 242 %** 로 나온 것이었다
`[측정]`. 값이 그럴듯한 범위였다면 "실데이터라 그런가 보다" 하고 넘어갔을
것이다. **자릿수가 어긋난 덕분에** 측정을 의심하게 됐다. 정정 후 0.226 %.

### 재사용 규칙

1. **AI 가 규칙을 여러 곳에 적용할 때, 각 적용 지점의 목적이 같은지 확인한다.**
   "같은 원칙이 목적에 따라 반대로 적용될 수 있는 곳이 있는가?" 를 되묻는다.
2. **일괄 수정 후에는 각 지점의 산출값을 개별로 확인한다.** 전체 테스트가
   통과해도 의미가 다를 수 있다 — 이번에도 테스트는 통과했다.

## R-4. AI 가 지표의 성질을 정확히 확인하지 않고 "불가능" 이라고 썼다

| | |
|---|---|
| 대상 | F-12 후속 정정의 "242 % 는 지표 정의상 불가능하다" |
| 처리 | **수정** |
| 연결 | F-12, `18_glossary.md` 3절 |

### 무엇이 틀렸나

`r_amp_err_pct` 는 상대오차 백분율이고 **상한이 없다.** 출력이 참값의 3.4배면
242 % 가 나온다. 즉 **수학적으로는 가능하다.**

불가능한 것은 *지표 정의상*이 아니라 **측정 맥락상**이다 — metric floor 는
참조에 40 dB 잡음만 더한, 사실상 참조와 같은 신호를 넣고 재는 값이므로
진폭이 2.4배 어긋날 수 없다.

### 검증 방법과 결과

`ecgdn/eval/morphology.py` 에서 정의를 직접 읽었다 `[코드]`:

`r_amp_err_pct = 100 × mean(|â_i − a_i| / |a_i|)`

### 재사용 규칙

1. **AI 가 "불가능하다", "말이 안 된다" 라고 쓰면 무엇에 비추어 그런지 되묻는다.**
   지표 정의상인가, 물리적으로인가, 이 측정 맥락에서인가 — 셋은 다르다.
2. **지표를 논할 때는 코드의 정의를 먼저 읽게 한다.** 기억이나 이름에서
   추정하지 않는다. 규약에도 넣었다.

## R-5. 외부 AI 검토를 받아들일 때도 같은 기준을 적용한다

| | |
|---|---|
| 대상 | 다른 AI 가 작성한 기록 체계 운영안 |
| 처리 | **부분 채택** |
| 연결 | R-1 ~ R-4 |

### 받아들인 것

- F-12·glossary 의 과장 지적 (→ R-2)
- 근거 등급에 `[코드]` `[문헌]` `[추론]` 추가
- 출처 없는 문헌 주장 지적 (F-8 의 "한 자릿수 dB")
- O 의 재발 방지 칸이 `—` 인 항목 지적 (→ O-6)
- R 계층 신설 자체

### 받아들이지 않은 것과 이유

| 제안 | 판단 |
|---|---|
| **F 를 12단계 템플릿으로** | **채택하지 않음.** 대부분 항목이 "해당 없음" 이 되고, 무엇보다 **칸을 채우려는 압력이 정확히 R-1 의 할루시네이션을 유발한다.** 현재 4필수+선택 구조가 자동 점검과 함께 작동 중이다 |
| 문서별 점수(8.5/10 등) | 근거가 불명확하고 실행으로 이어지지 않는다 |
| R 에 실험 내용 상세 서술 | F 와 중복되어 두 문서가 어긋난다. R 은 재사용 규칙만 담는다 |
| "모든 서술에 근거 태그" | 가독성이 무너지고 중요한 구분이 묻힌다. **사실 주장에만** 붙이는 원칙으로 대체 |

### 재사용 규칙

1. **외부 AI 검토도 F/D/O 와 같은 기준으로 검증한다.** 지적이 맞는지 코드와
   산출물로 확인한 뒤 반영한다 — 이번에도 탐색 구조를 코드에서 확인하고서야
   R-2 를 확정했다.
2. **"더 상세한 템플릿" 제안은 할루시네이션 압력을 늘리는지 먼저 본다.**
   기록 항목이 늘어날수록 빈칸을 채우려는 압력이 커진다.
