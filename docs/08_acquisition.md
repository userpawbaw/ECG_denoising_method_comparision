> 이 문서대로 수집하면 `scripts/estimate_real_snr.py` 와 EXP-F 가 바로 돌아간다.

## 0. 왜 잡음을 따로 모으는가

딥러닝 모델은 공개 데이터(MIT-BIH + NSTDB)로 학습한다. 그런데 실제 취득계의 잡음은
그것과 분포가 다르다 (ADC quantization, op-amp noise, 전원, 케이블, 전극 임피던스).
이 차이가 **domain gap** 이다.

해결책: **ECG 뿐 아니라 "잡음만" 도 별도로 측정한다.**
그러면 `MIT-BIH clean ECG + 우리 장비의 실제 잡음` 이라는 학습 데이터를 만들 수 있고,
모델이 우리 하드웨어가 실제로 만들어내는 잡음을 경험하게 된다.

## 1. 수집 세션 (총 약 42분)

| 세션 | 조건 | 길이 | 용도 |
|---|---|---|---|
| **S1** | 정상 안정 측정 (앉은 자세, 움직임 없음) | 5 분 × 3 회 | real-data 평가용 ECG |
| **S2** | 전극 부착, **팔/가슴 근육에 힘주기** 반복 (5초 수축 / 5초 이완) | 2 분 × 3 회 | EMG artifact |
| **S3** | 전극 부착, **케이블 흔들기 / 전극 가볍게 누르기** | 2 분 × 3 회 | electrode-motion artifact |
| **S4** | 전극 부착, **크고 느린 호흡 + 상체 좌우 이동** | 2 분 × 2 회 | baseline wander |
| **S5** | **전극을 몸에서 떼고** 입력에 더미 저항(예: 1 MΩ) 연결, 회로만 동작 | 2 분 × 2 회 | front-end/ADC noise floor |
| **S6** | S1 과 같은 조건을 **USB 전원 / 배터리 전원** 각각 | 2 분 × 2 회 | 60 Hz PLI 유무 비교 |

- **S2~S5 는 "잡음 전용" 이다.** S2~S4 는 전극이 붙어 있으므로 ECG가 섞이지만,
  분석 시에는 그 구간의 **잡음 성분**만 쓴다(ECG 는 beat 평균으로 제거).
  S5 는 ECG 가 아예 없는 순수 회로 잡음이다.
- S6 는 "notch 를 걸어야 하는가" 를 데이터로 판정하기 위한 것이다.
  `pli_ratio` 가 10 이상이면 `auto_notch` 가 작동한다.

### 안전/윤리 (졸업과제 범위에서 반드시 지킬 것)

- 본인 또는 동의한 성인만 측정한다. 측정 목적과 데이터 사용 범위를 사전에 설명한다.
- **전원에 직접 연결된 장비(USB로 PC에 물린 상태)** 에서 인체에 전극을 붙일 때는
  절연 상태를 확인한다. 가능하면 **배터리 전원 + 무선/광절연** 을 권한다.
- 수집한 신호는 개인 식별정보와 분리해 저장한다 (파일명에 이름/학번을 넣지 않는다).
- 본 데이터는 **연구용 신호처리 실험**에만 쓴다. 진단 목적이 아니다.

## 2. 하드웨어 / 소프트웨어

```
hardware/arduino_ecg_logger/arduino_ecg_logger.ino   # 고정 주기 ADC (기본 ASCII 500 Hz)
scripts/log_arduino.py                               # PC 측 CSV 기록기
scripts/serial_bridge.py                             # 실시간 시연용 브리지 (R-5)
```

**스케치는 하나이고 모드를 명령 1 바이트로 고른다.** 따로 두면 시연 당일
어느 것이 올라가 있는지 모르게 된다. 아무 명령도 안 보내면 **켜자마자
ASCII 500 Hz** 라, 아두이노 IDE 의 시리얼 모니터/플로터와 이 문서의 수집
절차는 **전과 똑같이** 동작한다.

| 명령 | 뜻 | 쓰는 곳 |
|---|---|---|
| `a` / `b` | ASCII / 바이너리 5 바이트 프레임 | 수집·디버깅 / **실시간 시연** |
| `2` `5` `1` | fs = 250 / 500 / 1000 Hz | 시연 250 · **수집 500** · EXP-F 1000 |
| `?` | 헤더 한 줄 (fs·모드·드롭 수) | 확인 |

바이너리 프레임과 그것이 필요한 이유(1 kHz 는 ASCII 로 115200 baud 를 넘는다,
손실을 세려면 `seq` 가 있어야 한다)는 `docs/30_realtime_demo.md` 6.2 에 있다.

배선 (AD8232 기준): `OUTPUT→A0`, `LO+→D10`, `LO-→D11`, `3.3V/GND`.

```bash
pip install pyserial
# 스케치를 업로드한 뒤
python scripts/log_arduino.py --port /dev/ttyACM0 --session S1 --dur 300 \
    --fs 500 --gain 1100 --note "seated, still"
```

- `--gain` 에는 **아날로그 프런트엔드의 총 이득**을 넣는다 (AD8232 기본 약 1100).
  이 값이 있어야 신호를 전극 단 mV 로 환산할 수 있다.
- 로거는 `lead-off` 비율과 **실측 샘플링률**을 출력한다. 설정과 5% 이상 다르면 경고한다.

## 3. 파일 규격 (반드시 지킬 것)

```
파일명: data/arduino/arduino_{session}_{YYYYMMDD}_{NN}.csv

# fs_hz=500
# adc_bits=10, vref_v=5.0, gain=1100
# session=S1, note=seated, still
t_ms,adc_raw
0,512
2,514
...
```

- **`fs_hz` 를 파일에 안 적으면 나중에 반드시 문제가 된다.**
- `adc_raw = -1` 은 lead-off (전극 떨어짐) 표시다. 분석에서 그 구간을 배제한다.
- `t_ms` 가 있으면 로더가 실제 샘플 간격을 검사해 헤더와 대조한다 (샘플 드롭 탐지).

## 4. 수집 후 절차

```bash
# (1) 적재 확인
python -c "from ecgdn.data.arduino import load_dir; [print(r) for r in load_dir('data/arduino')]"

# (2) 실측 SNR 추정 — "정말 15 dB 인가?" 에 답한다
python scripts/estimate_real_snr.py --in data/arduino
#    -> docs/08b_real_snr.md 생성

# (3) 그 값을 EXP-A 곡선에 표시
python scripts/make_report.py --real-snr <위에서 나온 중앙값>
```

`docs/04_snr_estimator_calibration.md` 의 **편향표와 함께** 해석해야 한다.
추정기는 잡음 종류에 따라 체계적으로 치우치며, 그 크기를 미리 재 두었다.

## 5. 수집 품질 체크리스트

측정 직후 아래를 확인한다. 하나라도 걸리면 그 세션은 다시 찍는 편이 빠르다.

- [ ] lead-off 비율 < 2 %
- [ ] 실측 샘플링률이 설정값의 ±2 % 이내
- [ ] ADC 값이 상/하단에 붙어 클리핑되지 않음 (0 또는 2^bits−1 이 연속으로 나오지 않음)
- [ ] S1 에서 R-peak 가 육안으로 명확히 보임
- [ ] S5(전극 미부착)의 잡음 RMS 가 S1 의 그것보다 **작음**
      (반대면 회로 자체가 주 잡음원이라는 뜻 → 아날로그 단부터 고쳐야 한다)
- [ ] S6 의 USB/배터리 조건에서 `pli_ratio_60` 값이 유의하게 다름

> **중요**: 디지털 후처리는 취득 단계에서 이미 소실된 정보를 되살리지 못한다.
> 클리핑, lead-off, 심한 포화는 어떤 알고리즘으로도 복원되지 않는다.
> 이 체크리스트는 "DSP 로 고칠 수 없는 문제" 를 먼저 걸러내기 위한 것이다.
