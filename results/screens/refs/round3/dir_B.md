## 1. 허브를 어떻게 탐색했나 — 그리고 **수확이 얇았다**

`api.github.com` **검색이 막혀 있다** `[측정]`:

```
api.github.com/search/repositories       → 403  "sessions are bound to their configured repositories"
api.github.com/repos/<남의 저장소>        → 403
api.github.com/repos/<우리 저장소>        → 200
raw.githubusercontent.com/<아무 공개>    → 200  (텍스트 · 이미지)
```

**찾을 수는 없고 읽을 수는 있다.** 그래서 허브를 **파일**로 잡았다 —
`github/explore` 의 **큐레이션 목록**이 `raw` 로 읽힌다:

```
raw.githubusercontent.com/github/explore/main/collections/<이름>/index.md
  → items: owner/repo 목록
```

있는 것으로 확인된 컬렉션 `[측정]`: `music` · `open-data` · `pixel-art-tools` ·
`design-essentials` · `web-games` · `text-editors` · `learn-to-code` ·
`front-end-javascript-frameworks` · `javascript-game-engines` · `clean-code-linters` ·
`government` · `policies` · `made-in-africa`.
없는 것: `data-visualization` · `visualization` · `science` · `dataviz` · `terminal-tools` · `design`.

**수확이 얇은 이유** `[측정]`: 저장소 **약 25 개**의 README 를 뜯어 이미지 경로를 뽑았는데,
**대부분의 스크린샷이 외부 이미지 호스트에 있다** — `imgur.com` · `steamstatic.com` ·
프로젝트 홈페이지 · `user-images.githubusercontent.com`. **전부 `000`.**
저장소 안(`raw`)에 스크린샷을 두는 프로젝트만 볼 수 있었고, 그게 **4 장**이다.

**돌아간 길**: 목록에 없는 저장소는 이름을 **기억에서 대고 즉시 확인**했다(맞으면 200,
틀리면 404 — 확인이 붙으니 기억 주장이 아니다). 계측·관제 계열 셋이 그렇게 나왔다.

## 3. 후보 — 4 개

고정값은 라운드 ② 와 같다(`round2/dir_B.md` 1 절). 이름은 **목적**, 골격은 §13 메뉴에서 하나.

### D1 — 「**기계가 지금까지 뭘 했는지** 보이는 화면」 · 골격 **⑦ 기록계 + 로그** (REF-01 · REF-02)

전면 레인 하나가 계속 그려지고, 오른쪽 280 px 에 **방금 한 일이 역순으로 쌓인다** —
「M04 적용 +11.8 dB」 「장면 교체 — 근전도 5 dB」. 문장은 `demo_bank` 에 이미 있다.
왼쪽 위에 **`돌고 있음 04:21:07`** 한 줄.

| | |
|---|---|
| 바꾸는 것 | 활동의 증거를 **모션에서 목록·숫자로** 옮긴다 |
| 그대로 두는 것 | 파형 기하 · 속도 · 단위 · 무채 팔레트 · 「저장된 결과 재생」 표기 |
| 3 m | 「왼쪽에 심전도, 오른쪽에 뭔가 계속 쌓임」 — 로그 **글자는 안 읽힌다**(의도) |
| 위험 | 로그가 **읽을 것을 늘린다.** 그리고 「돌고 있음 04:21:07」이 **실시간 계측 시간**으로 오독될 수 있다 → 「재생 경과」로 써야 한다 |
| 빌린 원리 | REF-01 「활동을 목록으로 증명한다」 · REF-02 「지속을 숫자 한 줄로」 |

### D2 — 「**7 레인을 좁은 세로 예산에 넣는** 화면」 · 골격 ② (REF-02)

C4(라운드 ②)의 개선판. 한 행이 **`SNR 5 dB [파형] +11.8 dB`** — 계열·그래프·값이 **같은 줄**.
범례를 안 만든다.

| | |
|---|---|
| 바꾸는 것 | 숫자를 그래프 **옆 같은 줄**에 붙인다 |
| 그대로 두는 것 | 단당 신호분 75.9 px · 7 단 531.0 px · 기하 |
| 3 m | 「일곱 줄, 아래로 갈수록 뭉개짐」 |
| 위험 | **C4 의 원래 문제가 남는다** — 줄 옆 숫자는 3 m 에서 안 읽힌다. 다만 **범례를 찾아 눈이 왕복하는 것**은 없어진다 |
| 빌린 원리 | REF-02 「한 줄 = 한 계열, 범례 없음」 |

### D3 — 「**멀리서와 가까이서 다르게 그리는** 화면」 · 골격 ① (REF-03)

같은 장면, 두 렌더링. attract(3 m)는 파형을 **굵은 마크**로, 사람이 다가오거나 만지면
**가는 선**으로 바뀐다. **데이터도 기하도 그대로**, 마크만.

| | |
|---|---|
| 바꾸는 것 | 거리에 따라 **마크 두께**를 바꾼다 |
| 그대로 두는 것 | 파형 기하 · 50 mm/s · 10 mm/mV · 격자 |
| 3 m | 「굵고 선명한 심전도」 |
| 위험 | **굵게 하면 미세 파형이 뭉개진다.** 어디까지가 표현이고 어디부터 기하 훼손인지 **선을 먼저 정해야** 한다(LOW 구역) |
| 빌린 원리 | REF-03 「거리에 따라 표현을 바꾼다 — 데이터는 그대로」 |

### D4 — 「**크롬이 곧 눈금인** 화면」 · 골격 ② (REF-02 · REF-04)

**크롬 층을 0 으로.** 지금 위 290 px 를 먹는 제목줄·칩 두 줄·판정 띠를 없애고,
**레인 테두리가 라벨과 눈금을 나른다** — 테두리 왼쪽 끊긴 자리에 `입력`, 오른쪽에 `+11.8 dB`,
위 테두리 눈금에 시간, 좌우 끝에 **±1 mV 그릇**.

| | |
|---|---|
| 바꾸는 것 | **크롬 290 px 를 회수한다.** 라벨·눈금이 테두리 안으로 들어간다 |
| 그대로 두는 것 | 격자 규약 · 단위 표기 · 「재생」 칩(이건 남는다 — 정직성 표기다) |
| 3 m | 「화면 전체가 기록지」 — 크롬이 안 보인다 |
| 위험 | 테두리에 낀 글자는 **3 m 69 px 를 못 맞춘다.** attract 의 큰 글자를 어디에 둘지가 이 방향의 미해결 지점이다. 그리고 그릇을 진하게 그리면 **격자(1.88:1)와 싸운다** |
| 빌린 원리 | REF-02 「레이블이 규칙선 안에 산다」 · REF-04 「괄호가 눈금 그릇」 |

## 4. 이 라운드가 드러낸 것

- **골격 메뉴에 없던 골격이 나왔다** — D1 의 「기록계 + 로그」. §13 메뉴 여섯 중 어디에도
  안 맞는다. **레퍼런스가 메뉴를 늘렸다** — 그게 레퍼런스가 일하는 방식이다.
  `02_benchmark` §13 에 **⑦** 로 넣었다.
- **§10(3 m 가독) 표가 못 답한 자리에 답이 왔다** — REF-03. 표는 「몇 px 이어야 하나」만
  말하고 「작게 만들 수 없으면 어떡하나」는 안 말한다. btop 의 답은 **마크를 바꾸는 것**이다.
- **수확이 얇다.** 저장소 25 개를 뜯어 카드 4 장. 갤러리 허브(ⓐ-1)가 로컬에서 붙으면
  「craft · wow 3 초」 칸이 채워진다 — 이 라운드는 **① 계측 · ② 관제 칸만** 채웠다.
  ③ 격자(C1)와 ④ 겹침(C2)의 **없는 원본은 여전히 없다.**
