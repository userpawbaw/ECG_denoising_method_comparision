# results/ext/structure — seed sweep 산출물 **공용 보관소**

이름은 「structure」로 시작했지만, **실제로는 D-24 seed sweep 의 모든 판이
여기 쌓인다.** 그렇게 하는 이유 하나 — 기준 arm `m06_l1` 을 여러 비교가
**공유**하기 때문이다. 구조 비교도, 용량 비교도, 손실 비교도 전부 `m06_l1`
대비이므로, 디렉터리를 나누면 같은 판을 세 번 돌리게 된다.

| 무엇을 묻나 | arm |
|---|---|
| 구조 (5.9 · 5.10) | `m06_l1` · `m07_l1` · `m08_l1` · `m09_l1` · `m10_l1` |
| 용량 (D-23 B) | `m06_l1_quarter` · `m06_l1_half` · `m06_l1` |
| 손실 (5.8.9) | `m06_l1` · `m06_l3` · `m06_l6` |

분석기는 `--base` 로 기준을 잡고 표에 있는 arm 을 전부 쓴다. 특정 비교만
보려면 `--base m06_l1` 로 두고 해당 행만 읽으면 된다.

    python3 scripts/analyze_seed_sweep.py results/ext/structure

**환경이 섞인다.** seed 0~3 은 Colab T4, seed 4~7 은 이 컨테이너 CPU 다.
**한 seed 의 모든 arm 은 같은 환경**이라 짝지은 비교는 유효하다 — 분석기가
섞임을 감지해 어느 판이 어디서 나왔는지 보여 준다. 캘리브레이션(F-41)에서
두 환경의 체계적 편향이 −0.002 dB 로 없다는 것을 확인했다.

체크포인트는 추적하지 않는다(`.gitignore`) — 같은 설정의 반복이라 재사용
가치가 없고, 수치는 `summary.json` · `sweep.csv` 에 있다.
